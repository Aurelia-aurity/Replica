# 이슈 #10: 전사 확인·수정·확정

`레플리카 화면 기획서_ver.2`의 SC-05와 2026-10-13 앱↔백엔드 API 초안을 참고했습니다. 수정은 `mobile/`에 한정합니다. 기본 실행은 합성 전사문을 사용하는 미리보기이며 실제 STT·파일 원본·개인화 처리가 아닙니다. 기록 관리 전체(업로드·목록·삭제)와 서버 합의 항목은 [RECORDS.md](RECORDS.md)에 있습니다.

## 화면과 동작

기록 목록에서 음성 ‘확인 필요’ 항목을 탭하면 전사 확인으로 이동합니다. 텍스트 저장 완료·음성 확정 저장 완료 항목은 기록 상세로 이동하고, ‘반영 중·전사 중’ 항목은 진입을 잠급니다. 전사 중·실패·결과 없음·조회 실패를 구분하고, 전사 중이면 5초마다 조용히 상태를 다시 읽어 완료되면 내용을 보여줍니다.

- **원본 재생(항목 1)**: 재생·일시정지·진행 막대와 `00:18 / 03:12`. 서비스가 원본 위치를 제공할 때만 동작하며(`RecordService.canPlayOriginal`), 처음 재생할 때 위치를 요청합니다. 제공하지 않으면 연결 전 안내를 표시합니다. 미리보기는 소리 없이 진행 시간만 보여줍니다.
- **확정 규칙 안내(항목 2)**: 확정하기 전 기록은 프로필·검색 색인에 들어가지 않음을 알립니다.
- **전사 구간 목록(항목 3)**: 구간마다 타임스탬프·화자·본문을 표시합니다. 시간을 탭하면 그 시점부터 재생하고, 재생 위치의 구간을 강조합니다. 인식이 불확실한 단어는 강조합니다. 서버가 구간 시간·화자를 주지 않으면 줄 단위로만 보여주며 시간이나 확률을 만들어 내지 않습니다.
- **구간 수정(항목 4)**: 본문을 탭하면 입력창으로 바뀝니다. 수정 내용은 로그인 세션의 메모리 초안에 즉시 보관되어 ‘나중에’로 나가거나 다시 열어도 유지되고, 로그아웃·계정 변경 시 폐기됩니다. 줄바꿈은 공백으로 접어 구간 수와 시간 정보를 지킵니다. ‘전체 텍스트로 수정’도 제공합니다. 앱 재시작을 넘는 로컬 영구 저장은 구현하지 않았습니다.
- **나중에 · 확정하기(항목 5)**: ‘확정하기’는 전사가 끝난 비어 있지 않은 초안에서만 활성화됩니다. 변경 내용을 먼저 저장하고 최신 버전으로 확정하며, 저장 중에는 ‘반영 중’을 표시하고 수정·중복 제출·뒤로가기를 막습니다. 확정 저장이 성공하면 ‘반영됨’으로 표시합니다. 확정 응답 유실 후 재시도는 먼저 버전 상태를 조회해 이미 확정된 버전을 재사용합니다. 확정본은 이 화면에서 직접 수정하지 않습니다.
- **STT 실패**: ‘전사에 실패했어요’와 오류 코드를 보여주고, 서비스가 재시도를 지원할 때만 ‘다시 시도’를 활성화합니다.

## 수정 충돌

저장은 `expected_updated_at`을 보내 409에서 충돌로 처리하고 입력을 유지합니다. 최신 내용을 다시 확인했을 때 서버 텍스트가 바뀌어 있으면 ‘서버 내용 사용 / 내 수정 유지’ 중 하나를 고르기 전까지 저장·확정을 막고, 서버의 최신 내용을 펼쳐 비교할 수 있습니다. 자동으로 덮어쓰지 않습니다.

## 초안 API 연결

- `GET /records/{id}`와 `GET /records/{id}/text-versions`: 가장 최신 revision의 초안 또는 확정본 조회. 응답에 선택 필드 `segments`가 있고 이어 붙인 본문이 `content`와 같을 때만 구간 정보로 사용합니다.
- `PATCH /text-versions/{id}`: 수정 내용과 `expected_updated_at` 전달.
- `POST /text-versions/{id}/confirm`: 확정본과 확정일 확인 후 성공 처리.

요청마다 현재 인증 헤더와 기존 30초 제한을 사용합니다. 기존 세션 조정자가 지연 응답·401을 처리합니다. 실제 서버 연결 검증은 하지 않았습니다.

## 명세에 없는 항목

- 구간 시간·화자·인식 신뢰도 필드, 원본 음성 조회 URL, 전사 재시도 API가 없습니다. 있으면 그대로 동작하도록 만들었고(`RecordApiExtensions`, `segments`), 제안 필드는 [RECORDS.md](RECORDS.md)의 합의 표에 정리했습니다.
- 2026-11-10 사용자 요청의 임시 규칙으로 텍스트 업로드 완료·음성 전사 확정 저장 성공을 ‘반영됨’으로 표시합니다. 실제 프로필 게시와 검색 색인 완료를 확인하는 백엔드 응답은 추후 연결해야 합니다. 시간 비교나 프로필 조회로 완료를 추정하지 않습니다.
- 새 revision 생성 API는 명세에 있으나 확정본 재편집 UX는 추가하지 않았습니다.
