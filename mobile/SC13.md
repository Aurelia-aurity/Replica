# SC-13 프로필 만들기 · 홈 대화 상대 카드

이슈 #94의 프론트엔드 구현입니다. 기준은 `레플리카 화면 기획서_ver.2`(SC-02·SC-13)와 `contracts/app-backend/api-spec.md`(기준일 2026-11-01)입니다. 백엔드·`contracts/`·DB는 변경하지 않았습니다.

**이슈 #94 본문과 달라진 범위(2026-11-12 결정).** 말투 프로필 기능은 이번 버전에서 구현하지 않기로 했습니다. 그래서 SC-07 말투 프로필 화면, 프로필 조회, 이름 수정, 프로필 다시 만들기, 항목 제외는 코드에서 삭제했고 이슈의 해당 완료 조건은 이 버전의 대상이 아닙니다. 대화 상대의 이름은 한 번 정하면 바꿀 수 없고, 프로필 삭제는 설정 화면을 만들 때 다룹니다. 삭제한 구현은 `feat/94-speech-profile-flow` 브랜치의 커밋 `3015633`·`b986a9b`에 남아 있어 다시 쓸 때 참고할 수 있습니다.

## 화면과 흐름

- **홈 대화 상대 카드(SC-02)**: 대화 상대가 있으면 이름과 텍스트·음성 대화 버튼을 보여 줍니다. 상태 줄·상세로 가는 탭·화살표는 없습니다. 대화 상대가 없으면 "프로필을 만들어 주세요"와 "프로필 만들기" 버튼만 보여 주고 대화 버튼은 없습니다. 목록을 불러오는 중에는 진행 표시, 실패하면 "대화 상대를 불러오지 못했어요."와 "다시 시도"를 보여 줍니다. "프로필을 만들어 주세요" 문구는 이 카드에만 씁니다.
- **SC-13 프로필 만들기**: 카드의 "프로필 만들기"로 들어오고, 저장하면 홈으로 돌아와 카드에 이름이 나옵니다. 앞뒤 공백은 제거하고 최대 50자(사용자가 보는 글자 수 기준, 이모지도 한 글자)이며, 비었거나 공백뿐이면 저장 버튼이 비활성입니다. 저장 중에는 저장·취소·뒤로가 막혀 중복 요청이 없고, 실패하면 입력값을 유지한 채 하단 알림과 "다시 시도"를 보여 줍니다. 취소·뒤로 가기는 아무것도 저장하지 않고 홈으로 돌아갑니다. 안내에 "저장한 이름은 바꿀 수 없어요."를 적어 두었습니다.
- **대화 화면(SC-09·SC-10)**: 상단 제목은 저장한 이름입니다. 홈 카드의 버튼, 홈의 최근 대화, 대화 탭(이력)의 새 대화·기존 대화 열기가 모두 같은 이름을 씁니다. 대체 제목('엄마'·'대화')은 없고, 대화 화면은 이름을 필수로 받습니다. 이름이 없거나 아직 불러오지 못한 상태에서 대화를 시작하거나 열려고 하면 열리지 않고 "대화 상대를 확인할 수 없어요. 홈에서 대화 상대를 확인해 주세요."만 보여 줍니다.

## 서버와의 통신

서버로 가는 사용자 입력은 대화 상대의 이름 하나입니다. 이름과 함께 앱이 만든 임의의 `persona_id`와 로그인 토큰이 갑니다. `persona_id`는 저장 응답이 유실돼도 대화 상대가 중복 생성되지 않게 하는 용도입니다.

| 통신 | 언제 | 보내는 것 | 서버 상태 |
| --- | --- | --- | --- |
| `GET /personas` | 홈 진입, "다시 시도" | 토큰만 | 구현됨 |
| `POST /personas` | 이름 저장 | `name`, `persona_id` | 구현됨 |
| `GET /personas/{id}` | 저장 응답이 불확실할 때만(연결 끊김·시간 초과·5xx·409) | 토큰만 | 구현됨 |
| `POST /sessions` | 새 대화 시작 | `persona_id`, `session_id`, `ai_notice_ack_at` | 구현됨 |
| `GET /sessions`, `GET /sessions/{id}`, `GET /sessions/{id}/turns`, `DELETE /sessions/{id}` | 대화 탭·최근 대화 | 토큰만 | 앱은 호출하지만 백엔드 라우터에 없음([SC11.md](SC11.md) 참고) |
| `POST /chat/text`, `/chat/voice`, `/chat/turns/{id}/tts` | 대화 | 메시지·음성 | 구현됨 |

말투 프로필 조회(`GET /personas/{id}/style-profile`)는 더 이상 호출하지 않습니다. 이름 저장이 불확실하게 끝나면 같은 `persona_id`를 조회해 이름이 같을 때만 성공으로 처리하고, 입력 거부(422 `INVALID_INPUT`)·인증 오류는 조회하지 않고 바로 실패로 처리합니다. 이름을 바꿔 다시 저장하면 새 `persona_id`를 씁니다.

새 대화는 홈 카드에서 고른 대화 상대의 `persona_id`로 만들어집니다(`startConversation`의 `persona` → `createForPersona`). 대화 상대가 여러 명이면 카드의 이름 자리가 선택 목록이 되고(main의 #114에서 들어온 선택 기능을 카드로 옮김), 고르지 않았으면 목록의 첫 상대를 씁니다. SC-13에서 새로 만든 상대는 바로 선택됩니다. 기존 대화를 열 때는 그 대화의 상대 이름(`Conversation.personaName`)을 제목으로 쓰고, 이를 알 수 없으면 선택한 상대의 대화일 때만 그 이름을 씁니다. 둘 다 아니면 열지 않고 안내만 보여 줍니다.

**이름이 서버에 필요한 근거.** `POST /personas`의 `name`은 필수입니다(`contracts/app-backend/api-spec.md`). 개인화 대화 생성 요청(`contracts/backend-ai/api-spec.md` 3장)에도 `persona.display_name`(1~50자)이 필수이고, 값은 백엔드·DB에 저장된 사용자 편집 가능 값을 그대로 전달합니다. 다만 지금 동작하는 baseline 대화(`/chat/text`·`/chat/voice`)에서는 이름을 쓰지 않고 서버에 저장만 됩니다. `display_name`은 이슈 #74에서 제안된 필드로 교차 검토가 끝나지 않았습니다.

## 더미 인증(미리보기)

더미 인증으로 로그인하면 메모리 구현(`MemoryPersonaService`, `MemoryConversationService`)을 쓰고 백엔드로 요청을 보내지 않습니다. 대화 상대는 비어 있는 상태로 시작하므로 실서버 계정과 같은 이름 설정 흐름을 거칩니다. 미리보기 대화는 정한 대화 상대의 id를 따릅니다. 데이터는 이번 로그인 동안만 메모리에 있고 로그아웃·계정 전환·앱 재시작 시 사라집니다.

## 구조

- `lib/profile/persona_models.dart`: 이름 규칙(`normalizePersonaName`, 최대 50자), `Persona`
- `lib/profile/persona_service.dart`: 서비스 인터페이스(목록·생성), 메모리 구현(더미 인증), HTTP 구현
- `lib/profile/persona_controller.dart`: 홈과 SC-13이 공유하는 상태. 늦게 도착하거나 화면이 사라진 뒤의 응답은 버립니다
- `lib/profile/persona_name_screen.dart`(SC-13), `persona_card.dart`(홈 카드), `persona_flow.dart`(SC-13 열기)
- `lib/services/api_client.dart`: 인증 헤더·로그인 세대 검사·타임아웃·오류 변환. 기본 타임아웃은 30초이고, 대화 서비스는 요청 종류별 시간(`request_timeouts.dart`)과 오류 코드(`AI_TIMEOUT`·`SPEECH_TIMEOUT`·`AI_UNAVAILABLE`)를 넘겨 씁니다. 시간 초과·연결 끊김은 재시도 가능한 네트워크 실패로 바뀝니다
- `lib/auth/auth_gate.dart`: 로그인 세대마다 컨트롤러를 만들고 로그아웃·계정 전환 때 함께 정리합니다
- `lib/history/history_screen.dart`: 이름이 없으면 대화를 시작·열지 않고 안내만 보여 줍니다

## 남은 일

1. **프로필 삭제**: 설정 화면을 만들 때 다룹니다. 서버에는 대화 상대 삭제 API가 없습니다. `contracts/app-backend/api-spec.md`와 DB 규격 어디에도 없고, 삭제 작업 객체의 `target_type`에 `persona` 값만 정의돼 있으며 "대상 전체 삭제는 DB 모듈 범위 밖"으로 적혀 있습니다. 삭제할 때 그 상대의 대화 이력·기록을 함께 지울지도 정해야 합니다.
2. **말투 프로필(SC-07)**: 다시 구현할 때는 서버의 `GET /personas/{id}/style-profile`(명세상 제안이며 백엔드에 라우트가 없음)부터 확정이 필요합니다. 이전 구현은 위 커밋을 참고합니다.
3. **대화 상대 선택**: 홈 카드의 선택 목록만 있습니다. 별도 선택 화면은 #89 후속입니다. 대화 서비스(`personas()`)와 대화 상대 서비스(`list()`)가 각각 `GET /personas`를 호출하는 중복이 남아 있습니다.
4. **`display_name` 계약**: 이슈 #74의 교차 검토가 끝나면 필드 이름과 형식을 확인해야 합니다.
5. **실서버 통합 검증**: 하지 않았습니다.
