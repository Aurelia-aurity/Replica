# SC-12 설정·계정 UI

이슈 #103의 **UI 우선 작업**입니다. `docs/requirements/레플리카 화면 기획서_ver.2.html`의 SC-12와 `contracts/app-backend/api-spec.md`, `contracts/backend-db/api-spec.md`, `mobile/AUTH_CONTRACT.md`를 참고했습니다. 수정 범위는 `mobile/` 내부이며, 이슈 전체의 기능 완료를 뜻하지 않습니다.

## 화면과 진입

- 홈 우측 계정 아이콘과 하단 설정 탭이 같은 SC-12를 표시합니다. 설정 탭의 선택 상태를 유지하고 홈·기록·대화 탭으로 이동할 수 있습니다. 기록 탭은 기록 관리(#72)의 기록 화면을 표시합니다.
- 기획서의 계정 카드, 대화·개인정보·계정 그룹, 흰색 둥근 카드, 구분선, 이동 화살표, 빨간 계정 삭제 항목을 반영했습니다. 기획서의 번호·설명 영역은 앱에 넣지 않았습니다.
- 계정 카드는 기존 인증 상태에서 이메일과 가입일을 전달받습니다. 가입일은 Supabase 세션의 사용자 `created_at`을 기기 시간대로 변환해 ‘YYYY.MM.DD 가입’으로 표시합니다. 값이 없거나 날짜로 읽을 수 없으면 ‘가입일 정보 미제공’, 이메일이 없으면 ‘이메일 정보 없음’을 표시합니다. 미리보기에는 합성 가입일을 넣지 않습니다.
- 세로 스크롤, 긴 이메일 줄바꿈, 화면 폭 최대 720으로 휴대폰·넓은 화면을 처리합니다. 미리보기 인증에서는 기존 세션 만료 확인 버튼도 유지합니다.

## 메뉴의 현재 동작

‘내 기록이 쓰이는 방식’ 독립 메뉴를 제거하고, 기존 사용 범위 안내 초안을 ‘기록 사용 동의 내역’ 시트 상단에 배치했습니다. 안내는 말투 프로필·검색·응답 생성의 사용 범위를 설명하는 앱 내 문구입니다.

| 메뉴 | UI 우선 구현 범위 |
| --- | --- |
| AI 생성 안내 다시 보기 | 기존 SC-08 내용을 재사용한 열람 전용 시트. 닫으면 설정으로 복귀. 체크박스·대화 시작 버튼이 없고 동의 시각을 생성하거나 대화를 생성하지 않음 |
| 말투 프로필 | 미연결 안내 시트. SC-07 진입, 선택한 상대 전달·프로필 조회는 후속 작업 |
| 기록 사용 동의 내역 | 기록 사용 범위 초안과 조회 준비 중 상태를 한 시트에 표시. 파일명·동의 시각·건수 조회는 미연결 |
| 로그아웃 | 기존 인증 서비스 동작을 유지하고 확인·취소 창을 추가. 확인 후 기존 콜백 호출, 중복 실행 방지. 콜백이 예외를 던지면 확인 창에 재시도 안내. 새 인증 API는 추가하지 않음. Supabase 인증의 결과는 아래 ‘로그아웃 결과 구분’ 참고 |
| 계정 삭제 | 기록 관리(#72)의 계정 삭제 시트를 그대로 실행. 안내 확인 후 삭제 요청, 완료 확인 뒤 로그아웃. 실제 계정에 미리보기 기록 서비스가 연결되어 삭제할 수 없으면 삭제 범위와 미지원 사유 안내 시트만 표시하고 요청을 보내지 않음 |

설정에서 AI 안내를 재열람해도 새 대화를 시작할 때는 기존 SC-08 이해 확인 절차를 다시 거칩니다. 로그아웃·계정 변경·세션 만료 시에는 기존 `AuthGate`의 계정별 화면 트리 정리 방식을 사용합니다.

### 로그아웃 결과 구분

Supabase 인증(`SupabaseAuthService.signOut`)에서는 ‘로컬 로그아웃 완료’와 ‘서버 요청 실패 안내’가 별개입니다. 서버 요청이 실패해도 이 기기의 로그인 상태나 설정 화면은 유지되지 않습니다.

| 구분 | 동작 | 확인 방법 |
| --- | --- | --- |
| 로컬 로그아웃 완료 | 서버 응답을 기다리기 전에 로컬 identity를 비우고 SDK 로컬 세션(`SignOutScope.local`)을 정리합니다. 이때 `AuthGate`가 계정 화면 트리를 제거하고 SC-01 로그인 화면을 표시합니다. 서버 결과와 관계없이 이 기기에서는 로그아웃된 상태입니다. | `test/supabase_auth_service_test.dart`: 원격 `/logout` 네트워크 실패에서도 호출 직후 identity가 비고, SDK 세션이 정리되며, 인증 헤더 요청이 실패함 |
| 서버 요청 실패 안내 | 원격 로그아웃 요청이 실패하면 `notice`에 ‘이 기기에서 로그아웃했어요. 서버 로그아웃 요청은 완료하지 못했어요.’를 넣고 `AuthFailure`를 던집니다. SC-01은 이 `notice`를 오류 문구 자리에 표시합니다. | `test/supabase_auth_service_test.dart`: `AuthFailure` 발생만 확인하며 `notice` 문구는 검사하지 않음. `test/sc12_test.dart`: 같은 순서(로컬 identity 먼저 비움 → 원격 실패 시 `notice` 설정 후 `AuthFailure`)를 따르는 합성 인증 객체로, SC-01에 `notice`가 표시되고 설정 화면·확인 창·재시도 문구·이전 이메일이 남지 않음을 확인함. `SupabaseAuthService`와 SC-01을 함께 띄운 테스트는 없음 |
| 설정 확인 창 실패 문구 | ‘로그아웃하지 못했어요. 다시 시도해 주세요.’는 `onSignOut` 콜백이 예외를 던질 때 확인 창에 나오는 문구입니다. 계정이 유지되는 경우는 identity를 비우지 않고 실패하는 콜백(모의 콜백 등)입니다. Supabase 실패에서 로그인 상태가 유지된다는 뜻은 아닙니다. | `test/sc12_test.dart`: 설정 화면만 띄우고 모의 콜백을 실패시켰을 때 재시도 안내가 나오고, 취소 후 기존 이메일이 보임 |

확인 창은 `useRootNavigator: false`로 계정별 화면 트리 안에 엽니다. 이전에는 `showDialog` 기본값에 따라 앱 최상위 Navigator에 열려, Supabase 서버 요청이 실패하면 SC-01로 이동한 뒤에도 확인 창이 남아 SC-01 위에 ‘로그아웃하지 못했어요. 다시 시도해 주세요.’를 표시했습니다. 2026-11-23에 수정했고, 위 `sc12_test.dart` 테스트는 수정을 되돌리면 실패하는 것을 확인했습니다.

## 남은 연동과 협의

- 동의 목록: #9와 백엔드 윤서준·DB 임재성의 제공 API 확인이 필요합니다. 명세의 `GET /records`는 제안 상태이며 `original_name`, `consent_at`, `consent_version`, `consent_scopes`를 확인해야 합니다. `items`, `limit`, `offset`으로 추가 조회하되 현재 조회 건수를 전체 건수로 표시하지 않아야 합니다.
- 조회 로딩·빈 목록·동의 정보 미제공·오류·재시도·추가 조회는 실제 서비스 연결 단계에 남깁니다. 목록은 현재 조회 준비 중으로 표시합니다. 동의 시각이 없는 기록을 완료로 간주하지 않아야 합니다.
- 회원가입 동의는 기록별 동의를 대체하지 않습니다. #103의 완료 조건에 맞춰 앱·백엔드·DB·PM과 안내 위치·최종 문구·동의 버전을 확정하고 검증해야 합니다. #25의 `training` 필드가 있어도 모델 학습 사용 여부는 별도 결정 사항입니다.
- 말투 프로필 이동과 상대·프로필 없음 처리: #94의 화면·선택 상대 계약 연결 필요.
- 계정 삭제: 2026-11-23 main의 기록 관리 계정 삭제 흐름을 SC-12에 연결했습니다. #11의 비밀번호 재확인·부분 실패 항목·재시도·전체 삭제 완료 조건은 해당 흐름과 서버 연동에서 확인이 필요합니다.

## 검증

2026-11-23 메뉴 삭제 후 정적 분석에서 문제 없음, 설정 화면 테스트 4개 통과, 변경 Dart 파일 포맷 확인 및 `git diff --check` 통과를 확인했습니다. 같은 날 main(#72 기록 관리, #127)으로 리베이스하며 홈 계정 시트의 계정 삭제를 SC-12 계정 삭제 항목으로 옮겼고, `test/record_deletion_test.dart`의 계정 삭제 테스트를 SC-12 경로로 갱신했습니다. 정적 분석 문제 없음, `flutter test --no-pub` 전체 287개 통과를 확인했습니다. 웹 빌드는 다시 실행하지 않았습니다. 아래 2026-11-09 전체 테스트·웹 빌드 결과는 최초 구현 당시 기록입니다.

2026-11-23 로그아웃 확인 창을 계정별 화면 트리로 옮기고 원격 로그아웃 실패 테스트를 추가한 뒤, 정적 분석 문제 없음, `flutter test --no-pub` 전체 289개 통과, 변경 Dart 파일 포맷 확인 및 `git diff --check` 통과를 확인했습니다. 실제 Supabase 서버나 실기기 검증은 아닙니다.

2026-11-09, 합성 계정·위젯 환경에서 확인했습니다. 실제 인증·서버·삭제 실행 또는 Android/iOS 실기기 검증이 아닙니다.

- `test/sc12_test.dart`: 두 진입점·탭 이동, AI 안내 재열람 후 새 대화의 동의 절차 유지, 미연결 메뉴 표시, 로그아웃 취소·중복 방지·모의 콜백 실패, 320×568·글자 1.8배·긴 이메일과 안내 시트 스크롤을 검사합니다.
- 기존 `test/auth_test.dart`의 로그아웃 테스트를 확인 창에 맞춰 갱신했습니다. 계정별 데이터·뒤로 이동 분리와 기존 인증 검증을 유지합니다.
- `flutter analyze --no-pub`: 문제 없음.
- `flutter test --no-pub`: 전체 110개 통과.
- `flutter build web --no-pub --dart-define-from-file=config/dev.local.json`: 성공.
- 변경 Dart 파일의 포맷 확인 및 `git diff --check`: 통과.

2026-11-23 현재 코드(메뉴 삭제 및 계정 삭제 흐름 연결 후)로 캡처 6장을 갱신했습니다. 실제 `ReplicaApp`에서 홈 계정 버튼으로 진입했으며, 390×844 논리 크기로 Windows 맑은 고딕과 Material Icons를 테스트에 로드해 위젯을 렌더링했습니다. 앱 테마나 글꼴 의존성은 변경하지 않았습니다.

합성 미리보기 계정으로 설정·동의 내역·AI 안내·로그아웃 확인·계정 삭제 확인을 촬영했습니다. 삭제 미지원 화면은 실제 인증 대신 비미리보기 상태를 반환하는 합성 인증 객체와 미리보기 기록 서비스를 조합해 재현했습니다. 서버 인증·로그아웃·삭제 요청은 실행하지 않았습니다. 가입일·동의 건수를 임의 생성하지 않았습니다.

캡처용 위젯 테스트 1개가 통과했고, 6장 모두 한글·아이콘·줄바꿈·화면 잘림을 육안 확인했습니다. 실제 기기 화면 캡처나 서버 연동 검증은 아닙니다.
