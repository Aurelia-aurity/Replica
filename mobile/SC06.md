# 이슈 #11: 기록·계정 삭제 확인과 결과

`레플리카 화면 기획서_ver.2`의 SC-06과 2026-10-13 앱↔백엔드 명세 초안을 기준으로 `mobile/` 안에 구현했습니다. 실제 자료나 원격 계정을 삭제하며 검증하지 않았습니다. 기록 관리 전체와 서버 합의 항목은 [RECORDS.md](RECORDS.md)에 있습니다.

## 기록 상세와 삭제

전사 확인 화면의 상단 삭제 아이콘 또는 확정 기록 상세 하단의 ‘이 기록 삭제’에서 확인 시트를 엽니다. 상세는 파일명·종류·올린 날·상태와 확정일·전사문 앞부분(‘전사문 전체 보기’로 구간 펼침)과 **개인화 반영 상태**(반영 중 · 반영됨 · 반영 지연 · 반영 실패 · 확인 필요)를 보여줍니다. 시트는 원본·전사문·검색 색인·프로필 반영분을 함께 지우는 범위와 되돌릴 수 없다는 안내를 표시하고, 요청 전 ‘취소’는 API를 호출하지 않습니다.

`DELETE /records/{record_id}`의 202 응답은 삭제 작업 접수로 처리합니다. 작업 ID를 유지하고 `GET /deletion-jobs/{job_id}`로 조회하며, `status=completed`와 빈 `remaining_steps`를 모두 확인한 경우에만 완료로 표시합니다. ‘completed’인데 남은 항목이 있거나, 조회가 실패하거나, 기록이 목록에서 사라진 것만으로는 완료 처리하지 않습니다.

## 진행·부분 실패·잔여 항목

- 접수 후 시트에 **단계별 목록**(원본 파일 · 기록·전사문 · 검색 색인 · 개인화 산출물, 계정은 계정 정보 추가)을 ‘삭제됨 / 진행 중 / 남음’으로 보여주고, 남은 항목을 한국어로 나열합니다. 부분 실패면 시도 횟수와 마지막 오류 코드(안전한 코드만)도 표시합니다.
- 진행 중인 작업은 시트가 열려 있는 동안 3초마다 최대 20회 자동으로 다시 확인합니다. **부분 실패한 작업은 자동으로 다시 묻지 않고** 사용자가 ‘상태 다시 확인’ 또는(서비스가 지원할 때) ‘다시 시도’를 누릅니다. 합성 미리보기는 사용자가 확인할 때만 완료됩니다.
- 요청 중에는 중복 조작·시트 닫기·뒤로가기를 막습니다. 접수 후 ‘닫기’는 삭제 취소가 아니며, 기록 목록에 삭제 요청 카드(남은 항목 포함)가 남아 상태를 다시 확인할 수 있습니다. 조회·재시도 응답은 기존 작업 ID와 삭제 대상이 일치해야 받아들입니다.
- 목록 새로고침에서는 `GET /deletion-jobs?limit=100&offset=...`를 이어 읽어 이전 작업을 복원합니다. 작업의 원본 경로나 manifest는 표시하지 않습니다. 삭제 접수된 기록은 숨기고, 완료된 기록의 메모리 초안은 제거합니다. 업로드를 취소해 정리한 예약도 같은 삭제 요청 카드로 보일 수 있습니다.

## 계정 삭제와 세션·캐시 정리

홈의 계정 버튼 → ‘계정 삭제’에서 모든 기록·대화·계정 정보의 삭제 범위를 확인하고, ‘되돌릴 수 없다는 것을 이해했어요’를 체크해야 요청할 수 있습니다. 서버가 완료를 확인한 뒤에만 다음을 합니다.

1. 화면의 기록 목록·전사 임시 초안·선택한 파일·화자 이름·삭제 상태를 비웁니다(`RecordController.clearLocalData`).
2. 계정별 화면과 대화 서비스를 폐기하고 로그인 화면으로 돌아갑니다.
3. 이 기기에 저장된 인증 정보를 지웁니다(`AuthService.completeAccountDeletion` → Supabase 로컬 로그아웃).
4. 로그인 화면에 ‘계정 삭제를 완료했어요’ 안내를 남깁니다(만료 안내와 구분).

완료 콜백은 요청을 시작한 로그인 세대에 묶여 있어 이전 세션의 결과가 새 로그인을 해제할 수 없습니다. 계정 삭제 요청·응답은 명세에서 미정이므로 **실제 API 어댑터에서는 요청을 비활성화**하고 임의의 `DELETE /account`를 호출하지 않습니다. 확정된 계약은 `RecordApiExtensions.deleteAccount`로 주입합니다. 이미 서버가 만든 계정 삭제 작업이 조회되면 상태 확인은 가능합니다.

## 재시도·미리보기

명세에는 실패한 삭제 worker를 재개하는 API가 없습니다. 실제 어댑터는 실패 시 ‘상태 다시 확인’을 제공하고 재시작 경로를 추정하지 않으며, 같은 작업 ID로 재개하는 요청이 합의되면 `RecordApiExtensions.retryDeletion`으로 주입합니다. 새 작업을 만들어 부분 실패를 감추지 않습니다.

기본 미리보기는 합성 기록·메모리 초안만 삭제하며 실제 파일·계정에는 영향을 주지 않습니다. 삭제 요청에서 pending 작업을 만들고, 사용자가 상태를 확인하면 합성 완료 결과를 돌려줍니다. 계정 삭제도 미리보기 세션만 종료합니다. 실제 삭제 worker·Storage·검색 색인·프로필·Auth 삭제 완료 검증은 백엔드 담당과의 통합 단계에 남아 있습니다. 이전 로그인 요청의 지연 응답과 401은 기존 세션 조정자가 처리하며, 권한 없음/404/원시 서버 오류는 자료의 존재나 내부 경로를 노출하지 않는 안내로 표시합니다.
