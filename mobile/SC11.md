# SC-11 대화 이력

이슈 #12의 프론트엔드 구현입니다. `docs/requirements/레플리카 화면 기획서.pdf` 13쪽과 제공된 앱 ↔ 백엔드 API 명세 초안(2026-10-13)을 기준으로 작성했습니다. 백엔드 코드는 변경하지 않았습니다.

## 화면과 흐름

- 하단 ‘대화’ 탭과 홈 ‘전체 보기’에서 이력을 엽니다. 홈에는 최근 두 대화를 표시합니다.
- 마지막 시각 내림차순으로 정렬하고 오늘, 이번 주, 이번 달, 이전 월·연도 단위로 묶습니다. 첫 질문, 마지막 시각, 마지막 입력 방식과 실제 질문·답변 수를 표시합니다.
- ‘새 대화’는 SC-08 이해 확인 후에만 대화방을 만듭니다. 기존 대화는 상세·턴을 다시 조회해 마지막 방식의 SC-09/SC-10으로 엽니다. 텍스트 전송은 기존 `session_id`를 유지합니다.
- 이력 화면의 ‘새 대화’는 텍스트·음성 선택 시트를 먼저 표시한 뒤 SC-08로 이동합니다. 방식 선택이나 AI 안내를 취소하면 대화방을 생성하지 않습니다.
- 메시지가 없는 대화는 처음 선택한 텍스트·음성 방식을 유지합니다. 메시지가 생기면 마지막 턴의 입력 방식을 사용합니다. 초안 API에는 초기 방식 필드가 없어 HTTP 연동에서도 이번 로그인 동안 앱에 보관하며, 메시지 없는 대화의 초기 방식을 앱 재시작 후 복원하려면 백엔드 필드 합의가 필요합니다.
- 다시 연 AI 답변에도 생성 배지와 고정 안내를 표시합니다. 처리 중인 턴이 있으면 새 전송을 막고 이력 새로고침을 안내합니다. 실패한 과거 턴은 별도 안내로 표시하고 새 메시지를 보낼 수 있습니다.
- 왼쪽 스와이프로 삭제 버튼을 노출합니다. 스와이프 없이도 항목의 더보기 버튼으로 삭제 확인 창을 열 수 있습니다. 취소 시 요청하지 않으며, 성공 전에는 항목을 지우지 않습니다. 실패 시 원위치에 유지하고 안내와 재시도를 제공합니다.
- 빈 목록, 최초 로딩, 목록·상세 조회 실패, 새로고침과 재시도를 처리합니다.

## 데이터와 API

기본 실행은 기존 `PreviewAuthService`를 유지합니다. 미리보기 대화는 이번 로그인 동안 메모리에만 보관하며 로그아웃·계정 전환·앱 재시작 시 초기화합니다. 합성 계정으로 실제 서버에 요청하지 않습니다.

`AuthGate`에 실제 인증 구현을 주입하면 `HttpConversationService`가 `BACKEND_BASE_URL`을 사용합니다. 각 요청에서 `AuthService.authorizationHeaders()`를 새로 얻고, 기존 `BackendService`로 401 처리와 로그인 세대 검사를 수행합니다. 계정이 변경되면 이력 저장소·화면·HTTP 클라이언트를 새로 만들고 이전 요청 결과를 버립니다. 토큰·메시지를 로그나 로컬 파일에 기록하지 않습니다.

| 동작 | 초안 API |
| --- | --- |
| 목록·상세 | `GET /sessions`, `GET /sessions/{session_id}` |
| 메시지 조회 | `GET /sessions/{session_id}/turns` |
| 새 대화 | `GET /personas`의 활성 상대 선택 후 `POST /sessions` |
| 이어 보내기 | `POST /chat/text`에 기존 `session_id`, 앱 생성 UUID `turn_id`, `message` 전달 |
| 삭제 | `DELETE /sessions/{session_id}`, 204일 때만 성공 표시 |

목록은 `limit/offset`, 턴은 `after_turn_no`로 끝까지 조회합니다. 턴 번호에 빈 번호가 있어도 마지막 실제 번호로 다음 페이지를 요청합니다. 목록 객체에 첫 질문·방식·메시지 수가 없어 턴에서 계산하며, 마지막 시각 기준 전체 정렬을 위해 모든 페이지를 읽습니다. 턴 조회 동시 실행은 최대 4개입니다. 대량 이력에서는 목록 요약 필드와 마지막 시각 기준 서버 정렬·페이지네이션을 백엔드에 추가하는 편이 효율적입니다.

요청은 30초 타임아웃을 사용하고 자동 재전송하지 않습니다. 실패한 동일 메시지의 수동 재전송에는 같은 `turn_id`를 사용합니다. AI 답변의 생성 표시 또는 응답 턴 ID가 규격과 다르면 정상 답변으로 표시하지 않습니다.

## 연동 한계

- 제공 명세는 합의 전 초안입니다. 실제 서버·실제 계정으로의 통합 검증은 수행하지 않았습니다.
- 기획서는 생성된 음성 파일도 삭제하도록 하지만 초안의 삭제 API는 대화방·턴의 DB 행만 삭제합니다. 앱은 음성 파일 삭제 완료를 주장하지 않습니다. 업로드 원본 삭제 API는 호출하지 않습니다. 생성 음성 정리는 백엔드 계약 확정이 필요합니다.
- SC-10은 기존 음성 화면 미리보기를 유지합니다. 음성 이력의 마지막 질문·답변과 키보드 전환은 제공하지만 녹음·STT·TTS·음성 파일 재생은 연결하지 않았습니다.
- 새 대화는 현재 별도 상대 선택 UI가 없어 반환된 활성 상대 중 첫 번째를 사용합니다. 상대 선택은 후속 화면 연동이 필요합니다.

## 검증

2026-10-28, Windows의 Flutter 테스트 러너에서 전체 59개 테스트를 통과했습니다. SC-11 추가 검증은 날짜 그룹, 목록·턴 페이지네이션과 빈 턴 번호, 인증 헤더, 기존 대화방 유지, 재전송 UUID, 지연 응답의 계정 분리, 401, 삭제 204, AI 안내, 빈 목록·조회 재시도, 삭제 취소·실패·재시도, 음성 방식 복원, 처리 중 전송 방지, 홈 최근 대화와 계정 전환을 포함합니다. 320×568 화면에서 넘침도 검사했습니다.

화면 캡처는 `docs/screenshots/issue12/`에 있습니다. 390×844 논리 크기와 Windows 한글 글꼴로 위젯을 렌더링한 합성 데이터이며 실제 기기 캡처가 아닙니다. Android/iOS 실기기와 실제 서버 연동은 미검증입니다.

`flutter analyze --no-pub`에서 문제 없음, `flutter build web --no-pub` 성공을 확인했습니다. 최종 삭제 버튼 숨김 보완 후 SC-11 관련 11개 테스트와 화면 렌더링을 다시 통과했고, 변경 파일의 Dart 포맷 및 `git diff --check`도 통과했습니다.
