# SC-01 로그인·회원가입 화면

2026-10-13에 제공된 `SC-01 로그인@2x.png`를 기준으로 수정했습니다. 기획서의 주황색 번호, 휴대폰 테두리, 설명 패널은 앱에 표시하지 않습니다.

## 반영한 구성

- 레플리카 제목과 ‘남겨둔 기록으로 다시 나누는 대화’ 소개 문구.
- 입력칸 위 이메일·비밀번호 라벨, 흰 배경과 둥근 테두리, 녹색 로그인 버튼.
- 이메일 형식 오류를 입력칸 아래에 바로 표시.
- 기본 비밀번호 마스킹과 눈 아이콘으로 표시 전환.
- 이메일·비밀번호가 모두 채워져야 로그인 버튼 활성화. 처리 중 중복 요청 차단.
- ‘처음이신가요? 회원가입’ 전환. 회원가입은 같은 레이아웃에 비밀번호 확인과 필수 개인 기록 처리 동의를 추가.
- 동의하지 않은 상태에서는 가입 불가. 전환 시 비밀번호·동의는 초기화하고 이메일은 유지.
- 로그인 실패는 입력을 유지하고 버튼 위에 ‘이메일 또는 비밀번호가 맞지 않아요’ 표시.
- 네트워크 실패 상태는 하단 SnackBar와 ‘다시 시도’ 버튼 표시. 실제 네트워크 요청 없이 주입한 더미 오류로 검증.
- 이미 가입된 이메일 상태는 이메일 입력 아래 안내하고 ‘로그인으로 전환’ 링크 제공. 더미의 합성 시험 계정으로 재현.
- 하단 잠금 아이콘과 ‘올린 기록과 대화는 내 계정에서만 볼 수 있어요.’ 안내.
- 작은 화면·키보드·큰 글자에서는 화면을 스크롤해 입력과 버튼에 접근.

## 구현 경계

수정·추가 파일은 `mobile/` 안에만 있습니다. 기존 플랫폼 생성 파일의 로컬 변경은 별도로 유지합니다.

화면은 `AuthService`에만 의존합니다. 가입에서는 `register(email, password, personalRecordsConsent)` 계약을 호출하며 서버·DB·AI 작업을 화면에 넣지 않습니다. 서비스의 오류 종류(`AuthFailureKind`)를 UI 상태로 변환합니다.

앱 시작점은 더미 `PreviewAuthService`만 주입합니다. 기존 Supabase SDK 어댑터는 활성화하지 않습니다. 더미는 합성 시험 계정으로 메모리 내 화면 이동만 제공하며 비밀번호·동의·개인 기록을 저장하지 않습니다. 성공하면 기존 인증 게이트를 거쳐 홈으로 이동합니다.

실제 인증·메일·세션 영구 저장·사용자 기록 저장·서버 권한 검사·RLS는 후속 담당 구현과 합의가 필요합니다. 하단 데이터 분리 문구는 기획서 안내 UI이며 실제 DB 권한 검증 결과를 뜻하지 않습니다.

‘미리보기 계정 안내’에서 시험 계정과 미연결 범위를 확인합니다. 이 안내는 본문 입력 흐름을 가리지 않는 별도 대화상자로 제공합니다.
