# SC-07 말투 프로필 · SC-13 말투 프로필 만들기·이름 수정

이슈 #94의 프론트엔드 구현입니다. 기준은 `레플리카 화면 기획서_ver.2`(SC-02·SC-07·SC-13)와 `contracts/app-backend/api-spec.md`(기준일 2026-11-01)입니다. ver.2는 `docs/89-ui-design-retouch` 브랜치(PR #91)에 있으며, `main`의 `docs/requirements`에는 이전 버전 PDF만 있습니다. **기획서와 이슈 #94가 다른 곳은 이슈를 따랐습니다.** 백엔드·`contracts/`·DB는 변경하지 않았습니다.

## 화면과 흐름

- **홈 대화 상대 카드(SC-02)**: 이름과 말투 프로필 상태를 표시합니다. 이름 영역을 누르면 대화 상대가 있을 때 SC-07, 없을 때 SC-13(새로 만들기)으로 이동하고, 저장하면 SC-07로 이어집니다. 대화 상대가 없으면 텍스트·음성 대화 버튼 대신 ‘말투 프로필 만들기’를 보여 줍니다. 목록 조회에 실패하면 다시 시도 버튼을 보여 줍니다.
- **SC-13**: 신규는 ‘말투 프로필 만들기’, 이름 수정은 ‘대화 상대 이름 수정’ 제목과 안내 문구로 바뀌고, 이름 수정에서는 기존 이름이 미리 채워집니다. 앞뒤 공백은 제거하고 최대 20자(사용자가 보는 글자 수 기준)이며, 비었거나 공백뿐이면 저장 버튼이 비활성입니다. 저장 중에는 저장·취소·뒤로가 막혀 중복 요청이 없고, 실패하면 입력값을 유지한 채 하단 알림과 ‘다시 시도’를 보여 줍니다. 취소·뒤로 가기는 아무것도 바꾸지 않고 이전 화면으로 돌아갑니다. 이름을 바꾸지 않고 저장하면 요청 없이 SC-07로 돌아갑니다.
- **SC-07**: ‘○○의 말투’ 제목, 갱신일, 자주 쓰는 표현·호칭·문장 끝맺음(항목별 카드, 항목이 없으면 ‘추출된 항목이 없어요’)을 스크롤 영역에 표시하고, ‘대화 상대 이름 수정’·‘프로필 다시 만들기’ 버튼은 기획서처럼 목록 아래에 고정합니다(항목이 많아도 항상 닿습니다). 다시 조회하는 동안과 재생성 중에는 이미 알고 있는 프로필을 그대로 보여 줍니다. 이름을 저장하면 홈 카드와 이후 여는 대화 화면(SC-09·SC-10) 상단 이름이 바뀝니다.

## API 연동 현황

| 기능 | API | 계약 상태 | 앱 | 실서버에서 |
| --- | --- | --- | --- | --- |
| 대화 상대 목록 | `GET /personas` | 구현 | 연동. 페이지를 끝까지 읽고 `active`만 사용 | 가능 |
| 대화 상대 생성(SC-13 신규) | `POST /personas` | 구현 | 연동. 앱이 정한 `persona_id`를 재시도 때 유지 | 가능 |
| 생성 결과 재확인 | `GET /personas/{id}` | 구현 | 쓰기 결과가 불확실할 때(연결 끊김·시간 초과·5xx·409)만 호출 | 가능 |
| 말투 프로필 조회 | `GET /personas/{id}/style-profile` | **제안** | 연동 코드 작성. `content.speech_style`의 세 항목 사용 | `main` 백엔드에 라우트가 없어 404 → ‘조회 실패’ 상태 |
| 이름 수정 | 명세에 없음 | - | **미연동.** 진입·취소는 동작, 저장은 비활성이며 안내 표시 | 저장 불가 |
| 프로필 다시 만들기 | 명세에 없음 | - | **미연동.** 버튼 비활성과 ‘(미연동)’ 안내 | 불가 |
| 항목 제외 | 명세에 없음 | - | **미연동.** UI 없음, 서비스 자리만 | 불가 |

생성 응답이 유실돼도 대화 상대가 둘로 늘지 않도록, 불확실한 실패 뒤에는 같은 `persona_id`를 조회해 이름이 같으면 성공으로 처리합니다. 입력 거부(422 `INVALID_INPUT`)·인증 오류는 조회하지 않고 바로 실패로 처리합니다. 이름을 바꿔 다시 저장하면 새 `persona_id`를 사용합니다.

새 대화는 홈 카드에 표시한 대화 상대의 `persona_id`로 만들어집니다(`HttpConversationService.selectedPersonaId`). 지정이 없으면 기존처럼 서버 목록의 첫 활성 상대를 씁니다. 여러 상대 중 고르는 UI는 없으며 홈 카드는 목록의 첫 상대를 보여 줍니다.

## SC-07 상태

| 상태 | 근거 | 표시 |
| --- | --- | --- |
| 조회 중 | 요청 진행 | 진행 표시 |
| 조회 실패 | 오류·시간 초과·응답 형식 오류 | 안내와 ‘다시 시도’ |
| 프로필 없음 | 서버가 `null` 응답 | ‘말투를 파악하려면 기록이 더 필요해요’, 이미 확정했다면 만드는 중일 수 있다는 안내, ‘기록 올리기’(SC-04). 기록 부족·생성 중·오래됨을 구분하지 않습니다 |
| 준비됨 | 프로필 객체 | 항목·갱신일, 이름 수정, 프로필 다시 만들기 |

프로필 다시 만들기는 진행 중에 버튼을 막고 ‘대화는 이전 프로필로 계속할 수 있어요’를 안내하며 이전 항목을 그대로 보여 줍니다. 완료하면 새 항목과 알림을, 실패하면 이전 프로필을 유지한 채 실패 알림과 다시 시도를 제공합니다. 끝난 결과 알림은 다음에 화면을 열 때 사라집니다.

## 미리보기 데이터

미리보기(더미 인증)에서는 `MemoryPersonaService.preview()`가 기획서 예시(엄마, 표현 4·호칭 2·끝맺음 4, 기록 11개, 10월 6일)를 제공합니다. SC-07에 ‘미리보기 데이터예요. 서버에서 받은 말투 프로필이 아니에요.’를 표시하고 홈 상태 줄에 ‘· 미리보기’를 붙여 서버 응답과 구분합니다. 이름 수정·다시 만들기·항목 제외도 이 메모리 데이터에서만 동작하며 로그아웃·계정 전환·앱 재시작 시 사라집니다. 미리보기는 대화 상대가 이미 있는 상태로 시작하므로 SC-13 신규 흐름은 테스트로 확인합니다.

## 구조

- `lib/profile/persona_models.dart`: 이름 규칙(`normalizePersonaName`), `Persona`, `StyleProfile`, 미제공 기능 예외
- `lib/profile/persona_service.dart`: 서비스 인터페이스(조회·이름 수정·재생성·항목 제외), 미리보기 구현, HTTP 구현
- `lib/profile/persona_controller.dart`: 홈·SC-07·SC-13이 공유하는 상태(대화 상대, 프로필, 재생성). 늦게 도착하거나 화면이 사라진 뒤의 응답은 버립니다
- `lib/profile/persona_name_screen.dart`(SC-13), `speech_profile_screen.dart`(SC-07), `persona_card.dart`(홈 카드), `persona_flow.dart`(진입 규칙)
- `lib/services/api_client.dart`: 인증 헤더·로그인 세대 검사·30초 타임아웃·오류 변환. 기존 `HttpConversationService`의 전송 코드를 그대로 옮겨 두 서비스가 함께 씁니다
- `lib/auth/auth_gate.dart`: 로그인 세대마다 컨트롤러를 만들고 로그아웃·계정 전환 때 함께 정리합니다

## 남은 일과 의존성

1. **백엔드·계약(#10, #74 논의 필요)**: `GET /personas/{id}/style-profile` 구현, 이름 수정(`PATCH /personas/{id}` 등), 프로필 다시 만들기(진행·완료·실패를 앱이 확인하는 방식 포함), 항목 제외와 제외 목록 유지, 프로필 응답의 근거 기록 수·생성 상태 필드. 제공되면 `HttpPersonaService`의 해당 메서드와 `supportedFeatures`만 연결하면 됩니다.
2. **SC-04 연결**: 기록 올리기는 이슈 #9 작업에 있습니다. 병합 뒤 `HomeScreen.onOpenRecordUpload`에 연결하면 SC-07의 ‘기록 올리기’가 이동합니다. 지금은 ‘아직 연결되지 않았어요’ 안내를 표시합니다. `feat/9-record-management`도 `home_screen.dart`·`auth_gate.dart`를 수정하므로 병합 때 충돌을 확인해야 합니다.
3. **항목 제외**: 채택 여부가 정해지면 SC-07 칩에 반영합니다(서버 API와 제외 목록 유지 포함).
4. **대화 상대 선택 UI**: 여러 상대를 고르는 화면은 없습니다(#89 후속).
5. 프로필이 없을 때 서버가 ‘기록 부족’과 ‘생성 중’을 구분해 알려 주면 SC-07·홈 카드 문구를 나눌 수 있습니다. 지금은 응답이 `null`뿐이라 ‘기록이 더 필요해요’ 제목에 ‘이미 확정했다면 만드는 중일 수 있어요’ 안내를 함께 둡니다. 기록 목록(`GET /records`)이 비어 있음을 확인하는 방법도 있으나 #9 작업의 API라 연결하지 않았습니다.
6. 기획서의 ‘기록 확정·삭제 시 자동 갱신’은 기록 흐름(#9, #10)을 연결할 때 컨트롤러의 `loadProfile()`을 부르는 지점을 정해야 합니다. 지금은 SC-07을 열 때와 다시 시도할 때만 조회합니다.

## 검증

2026-11-06 Windows에서 전체 Flutter 테스트 **186개**(기존 106개 + 신규 80개)와 `flutter analyze`가 통과했습니다. 기획서 UI 대조 검토 뒤(칩·고정 버튼·입력창 구성·버튼 비율) 다시 실행한 결과입니다. 웹 빌드로 SC-07·SC-13을 다시 열어 기획서 목업과 대조했습니다. 신규 테스트는 이름 검증·저장·취소·중복 방지·실패 시 입력 유지(`sc13_test.dart`), 프로필 상태·분기·이름 수정·재생성·홈 연동(`sc07_test.dart`), HTTP·미리보기 서비스와 컨트롤러(`persona_service_test.dart`)입니다. 320×568 화면과 키보드, 20자 이름, 항목 16개·512자 항목, 빈 항목에서 넘침이 없는지도 확인합니다.

- `flutter build web --dart-define-from-file=config/dev.local.json`이 성공했고, 이 빌드를 375×812 브라우저 화면에서 미리보기 계정으로 열어 홈 카드 → SC-07(항목·미리보기 라벨) → SC-13 이름 수정 저장 → SC-07·홈의 이름 반영 → 프로필 다시 만들기 완료 배너를 눈으로 확인했습니다. 재생성 진행 중 화면과 SC-13 신규·실패 상태는 테스트로만 확인했고 이 실행에서는 보지 못했습니다. 실기기 캡처는 아닙니다.
- 위 테스트는 가짜 서비스와 `MockClient`를 사용합니다. **실제 서버·실제 계정과의 통합 검증은 하지 않았습니다.** 특히 프로필 조회는 `main` 백엔드에 라우트가 없어 실서버 응답으로 확인하지 못했습니다.
- 실기기(Android·iOS)의 키보드·한글 입력은 확인하지 않았습니다.
- `dart format --set-exit-if-changed lib test`는 이 작업과 무관한 기존 파일 `lib/chat/ai_disclosure_sheet.dart`, `lib/shared/conversation_widgets.dart` 때문에 변경 이전부터 실패합니다. 이번에 만들거나 수정한 파일은 포맷을 통과합니다.
