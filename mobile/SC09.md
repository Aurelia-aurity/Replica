# SC-09 텍스트 대화

현재 브랜치의 SC-11 흐름을 유지하는 SC-09 구현입니다. 화면·연동 참조 문서는 [화면 기획서 ver.2](<../docs/requirements/레플리카 화면 기획서_ver.2.pdf>)와 [앱 ↔ 백엔드 API 명세](../contracts/app-backend/api-spec.md)입니다. API의 구현·제안·미정 상태는 해당 명세를 따릅니다. 변경 범위는 `mobile/` 내부입니다.

## 구현 내용

- 스크롤과 관계없이 유지되는 AI 안내, 오른쪽 사용자 메시지, 왼쪽 AI 답변과 응답별 생성 배지를 제공합니다.
- 공백 입력·2,000자 초과 입력·응답 대기 중 중복 전송을 차단합니다. 최신 메시지로 스크롤하며 180초 타임아웃(백엔드 오류가 먼저 오면 그 오류) 후 수동 재시도 또는 메시지 수정을 제공합니다.
- 백엔드의 안전한 오류 코드와 `retryable`을 사용합니다. 재시도 불가 오류는 메시지 수정만 제공하며 원문 오류를 표시하지 않습니다. 401·이전 로그인 세대의 응답은 기존 세션 처리에 따릅니다.
- 응답별 근거 기록 수를 누르면 파일명·날짜·선택 가능한 원문 조각을 시트에서 확인합니다.
- 명시적인 근거 없음 응답은 회색 배경·점선 테두리·‘근거 기록 없음’으로 구분합니다. 근거 정보가 전달되지 않은 응답은 별개의 ‘근거 정보 미제공’ 상태입니다. 답변 문장이나 빈 배열만 보고 근거 없음으로 추측하지 않습니다.
- `finish_reason: length`도 성공한 답변으로 유지하며 길이 제한 안내를 붙입니다. 모델 이름과 구간별 처리 시간은 응답 메타데이터로 유지합니다.
- 텍스트 대화방은 텍스트 방식으로 유지하며 음성 대화로 전환하는 버튼을 제공하지 않습니다. SC-11에서 다시 열어도 턴 ID와 AI 표시를 복원합니다. 현재 로그인 동안 보관한 추가 메타데이터도 복원합니다.

## 듣기

실제 인증·백엔드 서비스를 주입한 경우 매 재생 전에 ‘합성한 목소리예요’ 안내와 취소·재생 선택을 제공합니다. 최초 재생뿐 아니라 중지·재생 완료 후 다시 듣기와 실패 후 다시 시도에도 안내하며, 동의하기 전에는 TTS 요청이나 캐시 음성 재생을 시작하지 않습니다. 턴별 TTS API가 반환한 WAV/MP3를 `audioplayers`로 재생하며 준비 중·재생 중지·실패·다시 시도 상태를 표시합니다. 자동 재생은 하지 않습니다.

같은 화면에서 이미 받은 음성은 메모리에 보관해 다시 재생할 때 TTS를 중복 요청하지 않습니다. TTS·재생 실패는 텍스트 답변이나 대화 턴을 지우지 않습니다. 앱이 비활성화되면 재생을 중지하고, 화면을 나간 뒤 도착한 음성은 재생하지 않습니다. 화면 종료·계정 전환 시 플레이어를 해제합니다.

iOS·macOS·Linux의 재생에 필요한 임시 파일은 앱 전용 임시 폴더에 만들고 중지·화면 종료 시 제거합니다. Android·Windows·웹은 바이트 소스를 사용합니다. 오디오 구현은 [audioplayers 공식 문서](https://pub.dev/packages/audioplayers)를 참고했습니다.

## 명세에 따른 연동 경계

| 동작 | 사용 규격 |
| --- | --- |
| 텍스트 질문 | 인증된 `POST /chat/text`: 기존 `session_id`, 앱 UUID `turn_id`, `message` |
| 답변 | `answer`, `is_ai_generated`, `turn_id`, `finish_reason`, `model_name`, `timings` |
| 동일 질문 재시도 | 같은 `turn_id` 사용. 앱에서 이력을 본문에 추가하지 않음 |
| 듣기 | 인증된 `POST /chat/turns/{turn_id}/tts`, 본문 없음 |
| 합성 결과 | 일치하는 `turn_id`, `tts_status: ready`, 유효한 `audio_base64`·`audio_format` 확인 |

잘못된 턴 ID·AI 생성 표시·종료 이유·시간 값 또는 사용할 수 없는 음성 응답은 정상 결과로 표시하지 않습니다.

앱에서 타임아웃된 요청을 같은 `turn_id`로 다시 보낼 수 있습니다. 전송의 409 `CONFLICT`는 처리 중이거나 상태가 바뀐 경우에 올 수 있으므로, 앱은 서버 오류 코드와 `retryable`을 그대로 사용합니다. `retryable: false`이면 같은 요청의 재시도 버튼을 숨기고 이력 새로고침을 안내합니다. 서버가 재시도를 허용한 경우에는 같은 질문이나 녹음에 같은 `turn_id`를 유지합니다.

현재 `contracts/app-backend` 명세에는 RAG 근거 필드가 정의되어 있지 않습니다. 모버일은 후속 백엔드 필드를 `evidence: {status, items}`로 받을 준비가 되어 있습니다. `available`은 `items[].file_name/date/excerpt`를 근거 시트에 매핑하고, `none`은 명시적 근거 없음으로 표시합니다. 필드 누락·`unavailable`·`unknown`은 정보 미제공으로 유지하며 빈 배열만으로 근거 없음을 추론하지 않습니다. 서버 명세·구현에 이 필드가 추가되기 전에는 HTTP 응답이 `unknown`으로 표시되는 것이 정상입니다.

턴 목록에는 저장된 음성의 다운로드 주소·바이트가 없습니다. 이미 합성된 턴에 대한 TTS 재호출은 초안상 409이므로, 화면을 나간 후 기존 음성을 다시 받는 경로는 아직 없습니다. 현재 화면에서 받은 음성의 재생은 메모리 캐시를 사용합니다.

그래서 앱은 턴 목록·음성 응답의 `tts_status`를 읽어 `ready`인 턴(캐시된 음성이 없는 경우)에는 TTS를 요청하지 않고 ‘듣기 불가’와 “이 답변의 음성은 다시 받을 수 없어요. 답변 글은 그대로 볼 수 있어요.” 안내만 표시합니다. 음성 화면에서도 같은 턴은 재생 버튼과 ‘음성 다시 시도’를 숨깁니다. `tts_status`가 없거나 `failed`인 턴은 지금처럼 요청할 수 있습니다. 409 `CONFLICT`만으로는 합성 중인지 완료됐는지 구분할 수 없습니다. `ready`가 확인되지 않은 턴은 텍스트·음성 화면 모두 수동 재시도를 제공하며, 다시 재생하기 전에 합성 음성 안내를 표시합니다. 백엔드가 저장된 음성을 다시 내려주는 규격(#64 F5)을 정하면 이 잠금을 해제합니다.

## 미리보기와 검증

개발 미리보기 설정은 기존 인증·대화 미리보기를 유지합니다. `AUTH_MODE=supabase` 설정으로 실제 로그인하면 이 화면은 HTTP 대화 서비스를 사용합니다. 미리보기의 일반 질문에는 명확히 ‘합성 예시’로 표시된 근거 자료를 제공합니다.

현재 자동 검증 결과는 [README의 검증 기록](README.md#직접-실행-및-검증)을 참고하세요. 아래는 `175c242`에 남은 2026-11-04의 과거 기록입니다.

당시 전체 Flutter 테스트 **109개**와 `flutter analyze --no-pub`, `flutter build web --no-pub`가 통과했습니다. 추가 테스트는 근거 조각·출처 표시, 미제공/근거 없음 구분, 길이 제한, TTS 안내·취소·재시도·중지·재생 캐시, 화면 종료·앱 비활성화 후 지연 재생 방지, 타임아웃·수동 재시도, 오류 원문 비노출, API 요청과 메타데이터 복원을 검증했습니다. 기존 작은 화면·키보드 테스트도 통과했습니다.

당시 `flutter build apk --debug --no-pub`도 성공해 새 오디오 의존성을 포함한 Android 디버그 APK 컴파일을 확인했습니다. 현재 작업 상태의 빌드나 실제 기기의 음성 출력 검증을 뜻하지 않습니다.

`docs/screenshots/sc09/`의 캡처는 390×844 논리 크기·Windows 한글 글꼴·합성 데이터로 위젯을 렌더링한 것입니다. 실제 백엔드, 실제 음성 합성·출력, Android/iOS 실기기는 미검증입니다. 테스트의 오디오 출력은 가짜 플레이어로 검증했습니다.
