# 이슈 #9·#10·#11: 기록 관리 (SC-03 ~ SC-06)

SC-03~SC-06 화면기획서(`레플리카 화면 기획서_ver.2`)와 2026-10-13 앱↔백엔드 API 초안(`contracts/app-backend/api-spec.md`)을 기준으로 구현했습니다. 기록 API는 아직 **제안 단계**이고 백엔드에 기록 라우터가 없어, 앱은 초안에 정의된 요청만 보내고 정의되지 않은 항목은 임의로 만들지 않습니다. 이 문서는 서버 연동 완료나 팀 합의를 뜻하지 않습니다.

기능은 `lib/records/`에 있습니다.

| 파일 | 역할 |
| --- | --- |
| `record_models.dart` | 기록·파일·정책·업로드 시도(진행률·취소 토큰)·반영 상태 |
| `record_service.dart` | 서비스 인터페이스, 합성 미리보기, 세션 래퍼 |

## 실행과 화면

기존 미리보기 계정으로 로그인한 뒤 하단 **기록** 탭에서 시작합니다. 기본 실행은 합성 미리보기이며 파일을 서버로 보내지 않습니다.

### SC-03 기록 목록

- 전체·텍스트·음성 필터에 개수를 표시하고 생성 시각 내림차순, 같은 시각에는 ID 내림차순으로 정렬합니다. 파일명·종류·크기·업로드일을 표시하며, 실제 길이 값이 있을 때만 음성 길이를 표시합니다.
- 텍스트는 **반영 중 → 반영됨**, 음성은 **전사 중 → 확인 필요 → 사용자 확정 → 반영 중 → 반영됨**으로 표시합니다. 반영 중·전사 중 항목은 터치로 열리지 않습니다. 확인 필요 항목은 전사 확인·수정으로, 반영됨 항목은 읽기 전용 기록 상세로 연결합니다. 실패 항목에는 서비스가 지원하는 경우 ‘다시 시도’를 제공합니다.
- **상태 자동 확인**: 업로드·전사·반영이 진행 중인 기록이 있으면 목록이 화면에 있는 동안 5초마다 조용히 다시 조회합니다. 실패하면 5·10·20·40초로 간격을 늘리고, 진행 중인 기록이 없거나 화면을 떠나면 멈춥니다. 인증이 끝난 세션이면 더 묻지 않습니다.
- 로딩·실패·빈 목록·필터 결과 없음·재조회·아래로 당겨 새로고침, 삭제 요청 카드(남은 항목 표시)를 제공합니다.

### SC-04 기록 올리기

- 시스템 파일 선택기로 `.txt`, `.wav`, `.mp3`, `.m4a`를 고릅니다. 종류에 맞게 허용 형식을 제한하고, 형식·빈 파일·이름 255자·용량을 전송 전에 검증합니다. 취소하면 기존 선택을 유지합니다.
- **화자·제공자 선택(ver.2)**: `.txt`가 카카오톡 내보내기(안드로이드·PC·iOS 형식)로 인식되면 ‘누구의 말투를 반영할까요?’와 ‘이 기록을 제공한 사람은 누구인가요?’에 화자별 메시지 수를 보여줍니다. 한쪽에서 고른 사람은 다른 쪽에서 비활성이며, 두 사람을 모두 고르기 전에는 올릴 수 없습니다. 화자는 2명 미만이거나 일반 텍스트면 이 단계를 건너뜁니다. 분석은 **기기 안에서만** 하고 이름·메시지 수만 메모리에 두며, 파일 내용은 저장하지 않습니다. 파일을 바꾸거나 로그아웃·계정 삭제 시 지웁니다. 파일을 읽지 못해도 파일 전체로 올릴 수 있습니다.
- **선택 내용 전송은 아직 하지 않습니다.** 초안의 예약 요청에는 화자·제공자 필드가 없어, `RecordPolicy.sendSpeakerSelection`이 켜질 때만 `target_speaker`·`provider_speaker`를 보냅니다(기본값 꺼짐). 꺼진 동안 화면에 그 사실을 알립니다.
- 새 파일을 고르면 동의를 해제하고, 동의 없이는 올릴 수 없습니다. 동의 문구는 개인화 처리와 자료 사용 권한을 확인하며 모델 학습은 포함하지 않습니다.
- **진행률·취소**: 파일 전송 단계에서 `42% (3.1 MB / 7.4 MB)`와 진행 막대를 보여줍니다. 예약·전송 중에는 ‘업로드 취소’로 멈출 수 있고, 취소하면 이미 만든 예약·원본의 삭제를 `DELETE /records/{id}`로 요청합니다. 반환된 작업 ID와 상태를 기록 목록의 삭제 요청 카드에 보관하며, 진행 중·부분 실패·완료를 구분해 안내합니다. `completed`와 빈 `remaining_steps`를 모두 확인한 경우에만 삭제 완료를 알리고, 요청 실패는 카드에 남겨 다시 확인할 수 있습니다. 파일 전송이 끝난 뒤 결과 확인 단계에서는 취소할 수 없습니다. 취소 후 선택한 파일은 남지만 동의는 다시 받습니다.
- 업로드 중에는 중복 전송·파일 변경·동의 변경·뒤로 이동을 막습니다. 실패하면 같은 UUID·동의 시각으로 재시도하며, 원인(네트워크·권한 없음·파일 변경)을 구분해 안내합니다. 재시도 불가 오류는 전송 버튼을 비활성화합니다. 실패한 시도를 버리고 새로 시작하면 남은 예약을 정리합니다.

### SC-05 전사 확인 · 수정

- **원본 재생 바**: 재생·일시정지·진행 막대·`00:18 / 03:12`. 음성 원본은 처음 재생할 때에야 요청하며, 앱이 백그라운드로 가면 멈춥니다. 서비스가 원본 위치를 제공하지 않으면 재생 바 대신 연결 전 안내를 표시합니다.
- **전사 구간 목록**: 타임스탬프·화자·본문을 구간별로 보여줍니다. 시간을 탭하면 그 시점부터 재생하고 재생 위치의 구간을 강조합니다. 인식이 불확실한 단어(`uncertain_words`)는 노란 배경으로 강조합니다.
- **구간 수정**: 본문을 탭하면 입력창으로 바뀌고, 수정 내용은 로그인 세션 동안 임시 보관되어 ‘나중에’로 나가도 유지됩니다. 줄바꿈은 공백으로 접어 구간 수와 시간 정보를 보존합니다. ‘전체 텍스트로 수정’으로 한 번에 고칠 수도 있습니다.
- 서버가 구간 시간을 주지 않으면 줄 단위 구간만 표시하고 **시간을 만들어 내지 않습니다**.
- 목록에서는 전사 중 항목 진입을 잠그고 상태를 자동 조회합니다. 이미 열린 화면에서 처리 중으로 바뀐 경우에도 진행 표시와 비활성 확정 버튼을 보여줍니다. 실패 시 오류 코드와 다시 시도 버튼을 표시합니다.
- **수정 충돌**: 수정 저장은 `expected_updated_at`을 보내 409로 충돌을 감지합니다. 충돌 뒤 최신 내용을 다시 확인했을 때 서버 내용이 달라졌으면 **서버 내용 사용 / 내 수정 유지** 중 하나를 고르기 전에는 저장·확정할 수 없고 서버 내용을 펼쳐 비교할 수 있습니다. 어떤 경우에도 자동으로 덮어쓰지 않습니다.

### SC-06 기록 상세 · 삭제

- 파일명·종류·올린 날·상태와 확정일·전사문 앞부분(‘전사문 전체 보기’로 구간 펼침), 텍스트 기록은 본문 앞부분.
- 저장 완료 상태를 별도 영역에 표시합니다. 현재 ‘반영됨’은 아래 임시 저장 완료 기준을 사용합니다.
- 삭제 확인 시트는 함께 지워지는 항목을 나열하고, 요청 후에는 **단계별 진행(삭제됨/진행 중/남음)**, 남은 항목, 시도 횟수와 마지막 오류 코드를 보여줍니다. 진행 중인 작업은 3초마다(최대 20회) 자동으로 다시 확인하며, 부분 실패한 작업은 자동으로 다시 묻지 않고 ‘상태 다시 확인’ 또는(서비스가 지원할 때) ‘다시 시도’를 제공합니다. 접수 후 닫아도 삭제는 취소되지 않고 목록의 삭제 요청 카드에 남습니다.
- **계정 삭제**: 홈 계정 버튼 → ‘계정 삭제’. 범위를 확인하고 ‘되돌릴 수 없다는 것을 이해했어요’를 체크해야 요청할 수 있습니다. 서버가 완료(`completed` + 빈 `remaining_steps`)를 알린 뒤에만 세션을 끝내며, 이때 화면의 기록·초안·선택한 파일·화자 이름을 모두 비우고, 이 기기에 저장된 인증 정보도 지웁니다(`AuthService.completeAccountDeletion`). 로그인 화면에 ‘계정 삭제를 완료했어요’ 안내를 남기며, 요청을 시작한 로그인 세션에 묶여 있어 이전 세션의 늦은 응답이 새 로그인을 끊을 수 없습니다.

## 반영 상태 판정

2026-11-10 사용자 요청에 따라, 현재 UI의 ‘반영됨’은 서버 저장 성공을 기준으로 표시합니다. 실제 프로필 게시·검색 색인 완료를 판정하는 상태는 추후 백엔드 응답 규격과 연결해야 합니다.

| 단계 | 목록·화면 표시 |
| --- | --- |
| 텍스트 파일 업로드 중 (`uploading`) | 반영 중, 항목 진입 잠금 |
| 텍스트 업로드 완료 (`uploaded`·`processing`·`ready`) | 반영됨, 읽기 전용 기록 상세 |
| 음성 업로드·전사 처리 중 | 전사 중, 항목 진입 잠금 |
| 음성 `ready` + 미확정 전사문 | 확인 필요, 전사 확인·수정 |
| 음성 전사문 수정·확정 저장 요청 중 | 반영 중, 중복 조작·뒤로 이동 잠금 |
| 최신 음성 전사문 `confirmed` 확인 | 반영됨, 기록 상세 |

텍스트 기록의 조회 결과가 초안이어도 확인·확정 입력 화면은 표시하지 않습니다. 본문이 아직 준비되지 않은 텍스트 상세에서는 파일 정보와 본문 준비 안내를 제공합니다. 현재 화면 규칙으로 기록을 저장했다고 표시하는 것이며, 텍스트 초안을 자동 확정하는 서버 요청을 추가하지 않습니다. 음성은 기존 전사문 저장·확정 API를 사용하며 실패한 요청은 반영됨으로 바꾸지 않습니다.

상태 표시에는 프로필 갱신 시각·시간 경과 추정이나 프로필 조회를 사용하지 않습니다. 미리보기의 저장·전사 결과는 합성 예시입니다.

확정 여부는 기록 객체에 없어, 목록을 조회할 때마다 모든 `ready` 기록의 `GET /records/{id}/text-versions`를 다시 조회합니다(동시 최대 4건). 응답을 revision 내림차순으로 정렬해 최신 초안·확정본과 확정 시각을 반영합니다. 다른 기기에서 새 revision을 만들거나 확정할 수 있으므로 이전 확정 상태를 재사용하거나 30초 동안 조회를 생략하지 않습니다. 확인 결과는 각 목록 요청 안에서만 사용하며, 한 기록의 조회가 실패하면 그 기록을 ‘확인 필요’로 두고 다른 기록은 표시합니다.

## API 연결

`ApiRecordService`는 기본 앱에서 사용하지 않는 교체 가능한 초안 어댑터입니다. 실제 인증 서비스, HTTP 클라이언트, 검증된 기본 URL, 선택한 상대 ID, 정책과 파일 전송 구현이 모두 필요합니다. `ReplicaApp.recordServiceFactory`는 로그인 세션마다 독립된 서비스를 만들어야 합니다. HTTP 클라이언트의 생성·해제는 주입한 쪽에서 관리합니다.

| 단계 | 초안에 따른 동작 |
| --- | --- |
| 예약 | `POST /records`, UUID·상대 ID·파일 정보·동의 시각·버전 전달. `user_id` 미전달 |
| 예약 결과 불명 | 같은 UUID로 `GET /records/{id}` 조회. 404일 때만 같은 ID로 예약 재시도 |
| 원본 전송 | `RecordFileTransport.ensureUploaded` 주입. 진행률은 `upload.reportProgress`, 취소는 `upload.cancelToken` |
| 완료 알림 | `GET /records/{id}`로 상태 확인 후 아직 `uploading`이면 `POST /records/{id}/uploaded`. 전송 완료 단계는 재전송하지 않음 |
| 취소 정리 | 예약만 있고 `uploading`이면 `DELETE /records/{id}`. 이미 완료된 업로드는 지우지 않음 |
| 목록 | `GET /records?persona_id=...&limit=100&offset=...`, 페이지를 이어 읽고 ID 중복과 `deleting` 제외 |
| 전사 | `GET /records/{id}/text-versions`, `PATCH /text-versions/{id}`(`expected_updated_at`), `POST /text-versions/{id}/confirm` |
| 삭제 | `DELETE /records/{id}` → `GET /deletion-jobs[/{id}]` |
| 인증·오류 | 요청마다 인증 헤더 획득, 30초 타임아웃, 기존 `BackendService`의 401 세션 해제·이전 세션 결과 폐기. 서버 원문은 화면에 노출하지 않음 |

### 파일 전송 구현

`HttpRecordFileTransport`는 합의된 대상으로 원본을 스트리밍하며 실제 진행률과 취소를 처리합니다. 대상 URL·메서드·헤더는 `resolveTarget` 콜백이 정하고 앱은 추정하지 않습니다. 파일이 선택 후 바뀌면(`FILE_CHANGED`) 예약한 크기보다 더 보내지 않고 멈춥니다. 원본 덮어쓰기 방지와 결과 불명 복구는 합의된 프로토콜(대상 헤더·`alreadyStored` 콜백)의 책임입니다.

### 합의 전 기능을 꽂는 곳

초안에 없는 기능은 `RecordApiExtensions`의 콜백으로만 켜지며, 비어 있으면 해당 버튼이 비활성이거나 안내만 표시됩니다.

| 훅 | 켜지는 기능 |
| --- | --- |
| `retryProcessing` | 실패한 전사 다시 시도(SC-03·SC-05) |
| `retryDeletion` | 부분 실패한 삭제 작업 재개 |
| `originalAudio` | 원본 음성 재생 위치(SC-05) |
| `deleteAccount` | 계정 전체 삭제 요청 |

## 서버와 합의가 필요한 항목

아래는 앱이 가정하지 않고 비워 둔 부분이며, 제안 필드는 **합의 전 초안**입니다. 계약 문서(`contracts/`)는 이 작업에서 수정하지 않았습니다.

| 항목 | 현재 앱의 처리 | 제안 |
| --- | --- | --- |
| 원본 파일 업로드 방식·인증 | 전송 구현은 있으나 대상은 주입 | 직접 Storage 업로드/백엔드 경유 중 확정, 대상 URL·헤더 규격 |
| 지원 형식·최대 용량 | 형식 4종 고정, **25 MiB는 미리보기 값** | 서버 한도를 정해 `RecordPolicy`에 주입 |
| 전사 구간·타임스탬프·화자 | 있으면 표시, 없으면 줄 단위 | 텍스트 버전 객체에 `segments[{text,start_ms,end_ms,speaker,uncertain_words}]` 추가. 이어 붙인 `text`가 `content`와 같아야 함 |
| 원본 음성 조회 | 재생 연결 전 안내 | 인증된 재생용(서명) URL 발급 |
| 전사 실패 재시도 | 버튼 비활성 | 재요청 API |
| 화자·제공자 | 기기에서만 사용 | 예약 요청에 `target_speaker`, `provider_speaker`(제공자는 본인 동의 근거로 저장) |
| 기록별 반영 증거 | 사용자 요청의 임시 기준으로 업로드·전사 확정 저장 성공을 반영됨으로 표시 | 확정 전사 버전별 프로필 저장·적용과 검색 색인 준비를 모두 확인한 백엔드 응답 |
| 확정 여부 | 기록마다 텍스트 버전 조회 | 기록 객체에 확정 시각 포함 |
| 삭제 작업 재개 | ‘상태 다시 확인’만 | worker 재개 API |
| 계정 삭제 | 실제 어댑터에서 요청 비활성 | 요청·응답 규격과 삭제 worker |
| 음성 길이 | 표시 안 함 | 기록 객체에 `duration_seconds` |
