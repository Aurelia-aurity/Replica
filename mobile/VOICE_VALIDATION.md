# 실제 음성 입출력 검증

## 구현 경계

- 실행 조건은 [README의 환경 설정](README.md#실행과-환경-설정)을 따른다. 제공된 개발 설정은 더미 인증·메모리 미리보기이며, 현재 `selectAuthService`는 개발 preview 외에는 `UnconfiguredAuthService`를 선택한다. 설정 파일만 바꿔서는 실제 로그인이 켜지지 않는다. 로그인 통합에서 실제 `AuthService`와 인증 세션을 제공하면 HTTP 서비스를 사용한다. Supabase 초기화·인증 설정은 로그인 통합 작업에서 담당한다.
- 앱의 음성 네트워크 요청은 인증된 백엔드 `POST /chat/voice`, `POST /chat/turns/{turn_id}/tts`만 사용한다. STT/LLM/TTS 제공 업체나 스토리지 URL에 직접 연결하지 않는다.
- 녹음은 기본 16 kHz, 모노 PCM16을 WAV로 감싸 `question.wav`, `audio/wav`로 전송한다. 기기가 조정한 샘플레이트와 채널 수를 WAV 헤더에 반영한다. 최대 60초, 최대 25 MiB이며 전송 전 확장자·MIME·헤더·실제 PCM 길이도 검사한다.
- TTS는 백엔드 명세의 `audio_base64`와 `audio_format`을 사용한다. WAV/MP3 바이트를 메모리에서 재생하며 iOS/macOS/Linux는 앱 임시 파일을 사용하고 정리한다. URL 재생은 사용하지 않는다.
- 최초 재생, 일시정지 후 이어 듣기, 완료 후 재생, 실패 후 재시도 모두 합성 음성 안내에 동의해야 시작한다. 취소하면 합성 요청·재생을 하지 않는다.
- 전화·포커스 상실·헤드폰 분리 시 재생을 중단하고 자동으로 다시 재생하지 않는다. 녹음의 네이티브 pause 이벤트는 녹음 중단 오류로 처리하고 버퍼를 버린다. 백그라운드 전환은 녹음 시작·종료 대기 중에도 업로드를 취소한다. 이미 전송한 질문은 응답 또는 타임아웃까지 중복 녹음을 막고, 복귀 후 실패한 같은 녹음을 재전송할 수 있다. 늦게 도착한 이전 요청의 결과는 새 녹음의 종료·취소 버튼과 화면을 바꾸지 않는다.
- STT/LLM 실패는 서버 `stage`, 오류 코드, `retryable`을 사용한다. 같은 녹음 재전송은 같은 턴 ID를 유지한다. TTS 실패는 질문·답변 글을 보존하고 턴별 TTS API만 호출한다.
- `/chat/voice`가 LLM 실패 시 전사문을 반환하는 계약은 현재 없다. 이 경우 앱은 전사문을 추측하지 않으며, 성공 응답의 `transcript`를 표시한다.

## 현재 검증 상태 (2026-11-10)

최신 자동 검증 대상은 `a96b904`에 음성 화면 생명주기·같은 녹음 재시도 소유권의 로컬 미커밋 수정(PR #106 리뷰 1·2번)을 더한 상태다. 전체 **137개** 테스트(그중 `test/sc10_test.dart` **35개**)와 `flutter analyze --no-pub`가 통과했다. 기준 코드·과거 기록은 [README의 검증 기록](README.md#직접-실행-및-검증)을 따른다. 검증 이후에는 문서 정리만 반영했다.

음성 자동 검증은 백그라운드 전환 중 전송 잠금·같은 녹음 재시도 유지, 취소된 녹음 종료의 늦은 완료, 타임아웃 이후 새 녹음 조작 유지, 이전 전송의 성공이 최신 재시도 실패 전·후에 도착해도 턴 ID를 유지하는 경우를 포함한다.

Android/iOS 실기기 권한·마이크·전화·출력 검증과 실제 백엔드 10회 측정은 **미실행**이다. 자동 테스트의 가짜 녹음기·플레이어·HTTP 응답은 실제 성공률로 집계하지 않는다. 현재 작업 상태의 웹·Android·iOS/macOS 빌드는 다시 실행하지 않았다.

## 이전 검증 기록

`4769eae`에 남은 2026-11-04 기록은 전체 **113개** 테스트(음성 관련 **23개**)·정적 분석 통과와 `flutter build apk --debug --no-pub`의 Android APK 컴파일 성공이다. SC09·SC10·SC11의 전체 **109개** 기록은 이보다 앞선 `175c242`에 남은 기록이다. 두 결과 모두 현재 작업 상태의 검증 수치가 아니다.

당시 `audio_session` 의존성 다운로드 후 Windows 플러그인 심볼릭 링크 생성은 개발자 모드가 꺼져 있어 실패했다. 이는 과거 환경 기록이며, 현재 작업 상태의 Windows 데스크톱 실행은 별도 확인이 필요하다. iOS/macOS 빌드는 이 Windows 환경에서 수행하지 않았다.

## 실기기 실행 조건

로그인 통합이 완료된 실제 인증 세션, 접근 가능한 백엔드와 활성 대화 상대, Android 실기기 및 macOS/Xcode에 연결한 iPhone이 필요하다. 플랫폼 권한은 Android `RECORD_AUDIO`, iOS `NSMicrophoneUsageDescription`을 사용한다. 백엔드 주소는 HTTPS를 권장한다. 개발 Android HTTP는 debug 설정에서만 허용한다.

각 플랫폼에서 다음을 확인한다.

1. 마이크 권한 허용·거부·설정 이동 후 재허용. 거부 시 업로드가 없는지 확인한다.
2. 한국어 녹음 후 STT 질문·답변·합성 음성 수동 재생을 확인한다.
3. 무음·1분 제한·중복 탭, 화면 이탈 및 백그라운드 전환 중 녹음 종료를 확인한다. 전송 중 비활성화·복귀 후에도 새 녹음이 차단되고, 응답 성공 또는 실패 시 정상 표시·같은 녹음 재시도가 가능한지 확인한다. 타임아웃 후 새 녹음을 시작한 상태에서 이전 응답이 도착해도 종료·취소 조작이 유지돼야 한다.
4. 녹음·재생 중 전화 수신/통화, 타 앱 오디오, 헤드폰 분리를 확인한다. 전화 종료 뒤 자동 업로드·재생이 없어야 한다.
5. STT/LLM/TTS 각 실패를 서버 시험 환경에서 재현하고, 같은 녹음의 턴 ID 유지 및 TTS만 재시도하는지 확인한다.
6. 최초·이어 듣기·완료 후·실패 후 재생에서 안내 취소와 동의를 각각 확인한다.
