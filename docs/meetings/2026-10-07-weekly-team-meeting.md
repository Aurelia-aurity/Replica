# 2026년 10월 7일 팀 미팅 요약

회의일: 2026.10.07

## 회의 핵심

멘토님이 요청한 화면 설계서를 마련하고, 이슈·기능별 브랜치·PR 리뷰를 중심으로 협업 방식을 정리했다. 개발 환경과 파트별 역할을 맞추고, 다음 주 중간 발표에 활용할 작업 결과와 문서를 공유하기로 했다.

## 주요 결정 및 개발 방향

| 항목 | 정리 내용 |
| --- | --- |
| 화면 설계 | 프론트 담당이 수행계획서를 바탕으로 주요 화면과 동작 흐름을 작성한다. 팀 검토 후 개발 참고 자료와 발표에 활용한다. |
| 협업 절차 | 기능별 이슈 생성 → 브랜치 개발 → PR → PM·관련 파트 검토 → 병합으로 진행한다. 작업·버그·PR 템플릿과 한글 라벨을 활용한다. |
| 역할 분담 | 백엔드는 프론트와의 통신, DB 담당은 구조 설계·접근 함수, AI 담당은 모델·AI API 연동에 집중한다. 업무량에 따라 조정한다. |
| 구현 방식 | 공통 진입 파일을 함께 수정하기보다 파트별 모듈을 나누어 불러오는 구조를 사용한다. 완성된 기본 동작 확보를 우선한다. |

## 개발 준비 및 진행 현황

환경·인프라: AWS 서버 개설과 학교 GPU의 기본 모델 실행을 보고했다. Python 3.12 계열과 서버 포트 8000을 사용하고, 로컬 시험에는 Docker·로컬 DB 환경을 활용하는 방향이다.

협업 환경: 기본 프로젝트 구조, 이슈·PR 템플릿과 GitHub·Notion 동기화를 준비했다. CI는 각 파트 개발과 통합 상황에 맞춰 추가할 예정이다.

DB·화면: 기존 ERD 초안을 바탕으로 보완하고, 화면 설계 초안을 회의 중 제작·공유했다.

## 우선 후속 과제

① 각 파트의 다음 작업을 이슈로 등록하고 기본 화면·서버 상태 확인·AI 응답·DB 설계부터 진행한다.

② 작업 결과는 금요일 저녁까지 GitHub에 푸시해 발표자가 확인할 수 있게 한다.

③ 수행계획서·회의록·멘토링 자료를 저장소에 모으고, 진행 현황과 이슈·해결 방안을 기록한다.

④ 발표자는 LMS에 등록하고, 배경·목표·시스템 설계·진행 상황·향후 일정 중심으로 자료를 준비한다.

## 확인 사항 및 다음 일정

다음 주 월요일 중간 발표를 준비하고, 이후 회의에서는 지난주 계획·완료 현황·다음 작업을 공유한다. 기록 등록 주체는 우선 사용자가 고인의 기록을 올리는 방식으로 정리했다. 원본 음성 보관 여부와 음성 API의 추가 자료 반영 방식은 확인이 필요하다.
