# 사용자 확정 기록 기반 개인화 대화 시스템의 근거성 향상 설계와 평가
Design and Evaluation of Grounding Improvements for a Personalized Dialogue System Based on User-Confirmed Records

## 요약
개인 기록 기반 대화는 기록에 없는 사실을 만들거나 질문 속 거짓 전제를 받아들여 대상자에 대한 기억을 왜곡할 수 있다. 본 연구는 사용자가 확인한 기록을 사실 근거로 삼는 한국어 개인화 대화 시스템의 근거성 향상 방안을 설계하고 평가한다. 기록 질의응답, 지시 이행, 한국어 이해를 비교해 Qwen3-8B를 서비스 모델로 선정했다. 이어 근거 제한·페르소나 결합 프롬프트와 질문 단위 검색 기권·원기록 문맥 복원을 결합한 검색 v2를 구성했다. 연구팀이 구성한 한국어 합성 기록·질문 평가에서 핵심 정답률 60.8%에서 90.8%로의 상승과 사실 날조 36.7%에서 7.9%로의 하락을 확인했다.

## 1. 서론
개인 기록으로 특정 인물의 대화를 재현할 때 그럴듯하지만 틀린 정보는 대상자에 대한 기억과 이용자의 경험에 영향을 줄 수 있다 [1]. 일상 대화에는 생략과 문맥 의존이 많다. 청크만 검색하면 사건의 연결이나 화자를 놓칠 수 있고, 질문 속 거짓 전제나 기록에 없는 정보가 답변에 섞일 수도 있다.

본 연구는 사용자가 확인한 전사문과 화자를 사실 근거로 삼고, 사실 판단과 말투 반영을 분리한다. 모델 선정, 거짓 전제 방어 프롬프트, 질문 단위 검색 기권, 원기록 문맥 복원으로 이어지는 세 단계를 구성해 한국어 개인 기록 질의응답을 평가한다. 단계별 결과와 질문 유형별 차이를 비교한다. 본 연구는 세 단계 근거성 설계, 한국어 합성 기록 기반 단계별 평가, 앱·백엔드·데이터베이스의 통합 설계에 기여한다.

## 2. 관련연구
Generative Ghosts는 고인에 관한 그럴듯한 허위 정보가 기억과 유족에게 초래할 수 있는 위험을 다룬다 [1]. RoleFact는 허구 인물의 지식 경계 밖 응답을 줄이기 위해 검색과 원자적 사실 검증을 결합한다 [2]. 본 연구는 공개 대본 대신 사용자가 확인한 개인 기록을 사실 근거로 사용한다.

LongMemEval은 사용자–어시스턴트 대화 이력의 장기 기억과 답변 보류를 평가하며 거짓 전제 질문도 포함한다 [3]. 본 연구는 한국어 페르소나 기록에서 질문 단위 검색 기권을 평가한다. CREPE는 공개 지식 질의응답에서 거짓 전제를 탐지하고 바로잡는다 [4]. 본 연구의 근거 범위는 개인 확정 기록이다. SeCom은 주제 단위 기억과 압축 기반 검색 잡음 제거를 제안한다 [5]. 본 연구는 토큰 예산에 맞춰 검색 청크 주변의 원기록 문맥을 복원한다. KoBEST는 다섯 한국어 이해·추론 과제로 일반 언어 능력을 평가한다 [6]. 본 연구는 KoBEST를 기록 질의응답과 함께 모델 선정에 사용해 일반 한국어 능력과 기록 근거성을 구분한다.

## 3. 시스템 설계 및 구현

### 3.1 앱
설계. Flutter 기반 Android·iOS 앱은 홈·기록·대화·설정 흐름으로 구성했다. 로그인·가입은 앱에서 Supabase Auth로 처리하고 DB 테이블에는 직접 접근하지 않도록 설계했다. 기록 관리에는 이용 동의, 카카오톡 화자·제공자 선택, 음성 전사문 확인·수정, 프로필 생성·수정·삭제를 포함했다. 대화 화면에는 AI 생성 표시와 근거 파일명·날짜·발췌문, 음성 처리 단계를 제공하고 재생 전에 합성 음성임을 알리도록 설계했다. 기록 삭제 시 연관 자료와 프로필 반영분도 함께 제거하도록 했다.

구현. 로그인·회원가입, 텍스트·음성 대화, 이력 조회, 기록 관리 UI를 구현하고 더미 인증으로 앱 기능을 확인했다.

### 3.2 백엔드
설계. FastAPI 백엔드는 앱 요청을 라우터·서비스·클라이언트·DB 모듈에서 처리하도록 설계했다. 앱은 Supabase Auth로 인증한 뒤 Bearer JWT를 보내고 백엔드는 토큰에서 사용자 ID를 확인한다. 본문 ID는 권한 근거로 쓰지 않고 앱은 DB에 직접 접근하지 않도록 했다. 대화는 turn_id별 STT·AI·TTS 단계로 처리해 DB의 최근 20쌍을 AI에 전달하도록 설계했다. 재전송 시 완료된 단계는 재사용한다. 한 요청이 각 단계를 선점하고 시도 횟수가 일치할 때 결과를 저장하도록 했다. 응답 음성은 저장하지 않고 TTS 실패 시 텍스트를 유지하며 AI 생성 표시를 제공하도록 설계했다.

구현. FastAPI는 대화방 생성, 텍스트·음성 대화와 답변 TTS API를 제공한다. AI는 고정 응답 Mock과 계약 기반 원격 호출을, STT·TTS는 Mock을 지원한다. 백엔드 시험은 가짜 DB·AI를 사용했다.

### 3.3 데이터베이스
설계. Supabase PostgreSQL에서는 대화방·턴·기록·텍스트 버전·말투 프로필·검색 청크를 대화 상대별로 연결한다. 확정 텍스트를 수정하면 새 버전으로 기록하고, 프로필의 원본 개정 번호를 저장해 자료 변경 시 갱신 대상으로 표시한다. 텍스트 버전·검색 청크는 사용자·대화 상대 식별자를 상위 기록과 함께 검사하는 복합 외래 키를 사용하며, 조회에는 RLS를 적용하고 쓰기 권한은 백엔드에서 확인한다. 검색 대상은 동의된 현재 확정본으로 한정하고 임베딩 차원 제약과 복합 인덱스를 사용한다.

구현. 원격 Supabase에 스키마를 적용하고 Python 접근 함수를 반영했다. 합성 자료와 임시 계정 2개로 저장·조회, 계정 분리, 일반 사용자 토큰의 직접 쓰기 및 서버 전용 함수 호출 차단, 턴 실행권과 이전 시도 결과 거부, 확정본 검색과 삭제 요청 기록 제외를 확인했다.

## 4. 실험 설계 및 평가

### 4.1 평가 데이터
평가에는 연구팀이 구성한 한국어 합성 기록·질문을 사용했다. 실제 개인 기록은 개인정보 문제로 제외하고, 지어냄과 거짓 전제 수용이 드러나도록 질문 유형을 나누었다. 데이터는 가상 페르소나 6명, 기록 240건(일기 120건·대화 120건), 질문 240개로 구성한다. 질문 유형은 단일 기록 사실, 다중 기록 추론, 거짓 전제, 모호성, 답 없음, 일상 대화이며 유형별 문항 수는 표 1과 같다. 목표 말투는 하게체·해요체·반말이고 말투별로 80문항씩이다. 사실 질문에는 필수 사실 요소와 허용 별칭을 정했다.

표 1. 평가 데이터셋 구성

| 질문 유형 | 문항 수 |
|---|---:|
| 단일 기록 사실 | 48 |
| 다중 기록 추론 | 48 |
| 거짓 전제 | 48 |
| 모호성 | 24 |
| 답 없음 | 48 |
| 일상 대화 | 24 |
| 합계 | 240 |

최초 후보 모델 비교(표 2)에는 기록 질의응답 20문항과 지시 이행 20문항, KoBEST 다섯 과제를 사용했다. 추가 모델 비교에서는 6개 후보별로 기록 질의응답·지시 이행·근거성 문항을 각각 120개씩 적용했다. 별도의 단계별 프롬프트·검색 비교에는 위 합성 데이터 240문항을 사용했다.

### 4.2 실험 설정 및 평가 방법
평가 기준과 판정 절차는 실행 전에 고정했다.

모델 비교 후보는 단일 48GB GPU에서 구동할 수 있는 8B 이하 Apache-2.0 공개 모델 6종으로 정했다. 기존 기준 모델 Qwen2.5-7B-Instruct, Qwen3 계열, 국내 기업이 공개한 한국어 모델 A.X와 Kanana를 포함했다. 기록 질의응답 성공은 유효한 JSON을 출력하고 모든 정답 슬롯을 충족했을 때로 판정했다. 지시 충족률과 KoBEST도 비교했다. 기록 질의응답과 지시 충족의 최고값에서 각각 5%p 이내인 후보를 남기고, 그중 KoBEST가 가장 높은 모델을 택했다. 표 2의 근거성(1–5점)은 작성자 1인의 탐색적 점검이며, 추가 근거성 평가는 규칙 검사와 자동 판정(LLM 기반)으로 산출했다. 평가자가 달라 두 점수의 증감을 직접 비교하지 않았다.

단계별 비교에서는 Qwen3-8B를 고정했다. 기본 프롬프트는 간결한 한국어 답변을 요구한다. 여기에 기록 밖 내용을 사실로 말하지 않고 거짓 전제를 바로잡는 근거 제한 지시와 대화 상대의 말투 지시를 더해 결합 프롬프트를 구성했다.

그림 1은 유사도 상위 5개 청크를 그대로 전달하는 v1과 질문 단위로 검색을 기권하거나 원기록 문맥을 복원하는 v2의 근거 구성 차이를 보여준다. 검색 v2는 KURE-v1 임베딩의 L2 정규화 코사인 유사도를 사용한다. 최고 유사도가 0.5459 미만이면 빈 근거를 반환하고, 기준 이상이면 상위 3개 결과에서 대화 전후 3턴 또는 일기 전문을 복원한다. 복원 문맥이 토큰 한도를 넘으면 청크로 대체하고 점수가 낮은 기록부터 제외해 근거 JSON을 Qwen3-8B 토크나이저 기준 2,000토큰 이내로 맞춘다. 검색 설정은 별도의 개발 질문 40개로 고정했다. 설정 근거가 된 과거 비교에서 원본 코퍼스 상위 5개 청크가 필수 근거를 모두 포함한 비율은 66.7%였다. 별도 인코더 비교에서는 상위 5개 결과가 필요한 근거를 모두 포함한 비율이 KURE-v1 80.0%, multilingual-e5-small 53.3%였다. 이 값들은 현재 240문항 평가가 아니라 설정을 정할 때 참고한 과거 비교다.

공통 생성에는 탐욕적 디코딩을 적용하고 최대 출력을 160토큰으로 제한했다. 단계별 비교는 기본 프롬프트+기존 검색, 결합 프롬프트+기존 검색, 결합 프롬프트+개선 검색, 정답 근거 입력(진단용)의 네 조건으로 구성했다. 질문·조건마다 한 번 생성했으며 조건 간에는 한 요소씩 바꿨다.

검색은 사실 질문의 필수 슬롯·별칭 포함률과 답 없음 질문의 빈 근거 반환률로 평가했다. 응답은 규칙 검사와 대규모 언어 모델 기반 자동 판정으로 채점하고 위험·불확실 응답은 재판정했다. 통과 응답에서도 조건·질문 유형·하게체 여부로 층화 추출한 25%(올림)를 자동 재판정했다. 표본 판정 불일치율 5.88%가 사전 기준을 넘어 전체 응답을 재판정했다. 일상 대화에서 질문을 그대로 반복한 응답은 정답으로 세지 않았고, 말투와 종결어미는 따로 검사했다. 핵심 정답은 필수 사실 포함, 사건 구분, 거짓 전제 정정, 답 없음의 적절한 보류, 일상 대화의 적절한 응답으로 판정했다. 기록 밖 개인 사실을 추가하면 지어냄으로, 전달된 근거로 답할 수 있는 질문을 거절하면 과잉 거절로 분류했다.

필수 사실 완전 포함률은 단일 기록 사실·다중 기록 추론·거짓 전제 각 48문항과 모호성 24문항을 합한 사실 질문 168문항을 분모로 삼았다. 핵심 정답률·사실 날조율·말높임 일치율은 전체 240문항, 거짓 전제 정정률·안전한 답변 유보율은 해당 유형 48문항을 분모로 계산했다.

### 4.3 평가 결과 및 논의
표 2는 최초 후보 모델 6종의 결과다. 기록 질의응답과 지시 이행의 최고값에서 각각 5%p 이내인 후보 가운데 KoBEST가 가장 높은 Qwen3-8B를 선정했다. 기준 미달 후보를 먼저, 선정 모델을 마지막 행에 배치했다.

표 2. 후보 모델 비교

|---|---:|---:|:---:|---:|---:|

| Qwen3-4B-Instruct-2507 | 60.0 | 75.0 | 통과 | 59.6 | 3.30 |

추가 비교에서 Qwen3-4B-Instruct-2507과 Qwen3-8B의 기록 질의응답 성공률은 각각 67.50%와 60.83%, 지시 충족률은 각각 74.17%와 83.33%였다. 두 지표의 결과는 엇갈렸고, 각 지표의 최고값에서 모두 5%p 이내인 후보는 없었다. 기존 기준으로 새 후보를 정할 수 없어 서비스 모델은 최초 선정을 유지했다.

## 5. 결론
본 연구는 사용자가 확인한 기록을 사실 근거로 삼는 한국어 개인화 대화 시스템을 설계하고, 모델 선정부터 프롬프트와 검색 개선까지 단계별로 평가했다. 합성 기록·질문 기반 오프라인 평가에서 결합 프롬프트는 주로 답 없음 문항에서 안전한 유보를 늘렸고, 개선 검색은 다중 기록 추론의 정답률을 높였다. 관찰된 개선은 이처럼 평가 항목별로 나뉘어 나타났다. 실제 개인 기록이나 앱·백엔드·데이터베이스 통합 환경에서의 성능은 확인하지 않았으며, 일상 대화 정답은 2/24(8.33%), 날조는 19/24(79.17%), 말높임 일치율은 43.3%였다. 또한 기존 검색과 개선 검색 모두 답 없음 질문에 빈 근거를 반환하지 못했다. 후속 연구는 검색 기권, 일상 대화 생성, 말투 제어를 개선하고 통합 환경에서 성능을 평가한다.
