# 사용자 확정 기록 기반 개인화 대화 시스템의 설계와 오프라인 평가
Design and Offline Evaluation of a Personalized Dialogue System Based on User-Confirmed Records

김민균, 김태환, 윤서준, 임재성, 박정규(LG CNS), [교신저자 — 대기]
[소속·이메일·영문 저자 표기 — 양식 조판 시 작성]

## 요약
본 논문은 사용자 확정 기록을 활용하는 개인화 대화 시스템의 설계와 AI 구성요소의 오프라인 평가를 제시한다. 한국어 합성 기록으로 후보 모델과 프롬프트를 비교하고 질문 단위 기권·원기록 문맥 복원을 결합한 검색 v2를 평가했다. 보정 코퍼스에서 완전 슬롯 문항은 42/60에서 57/60으로 늘었다. 신규 사건군에서는 자동 판정(전체 문항)과 작성자 수동 채점(held-out 48건 표본, 조건당 16건)을 구분했다. 종단 간 서비스 연동은 진행 중이다.

## 1. 개요
개인 기록 대화는 기록에 없는 내용을 지어내거나 질문의 거짓 전제를 받아들일 수 있다. 사후 아바타에서는 동의·투명성·기록 통제도 고려해야 한다. 사용자 확정 기록은 사용자가 올린 내용을 전사하고 화자를 확인한 뒤, 사용자가 확정한 기록만 응답 근거로 쓰는 설계 방향이다. 말투 정보는 사실 근거와 분리한다. 기록 변경·삭제 전파가 실제로 이뤄지는지는 후속 검증 사항이며, 현재 검증 완료를 뜻하지 않는다.

RQ1은 한국어 합성 기록 대화에서 후보 모델별 과제 수행과 프롬프트 변경에 따른 거짓 전제 대응·핵심 정답·과잉 거절의 상충 관계를 묻는다. RQ2는 질문 단위 기권과 원기록 문맥 복원을 결합한 검색 v2의 보정 코퍼스 성능 및 신규 사건군 held-out의 무근거·검색·gold 조건을 자동·수동으로 평가한다.

기여는 세 가지다. C1은 여섯 후보 모델의 기록 QA·지시 이행·작성자 근거성과 외부 KoBEST를 분리하고 조건부 모델 추천의 근거와 한계를 제시한다. C2는 프롬프트 실험별 안전 정의를 유지하며 답변 정답·과잉 거절의 상충 관계를 보고한다. C3은 검색 v2 결과와 held-out 자동 전체 판정·작성자 수동 48건 표본을 구분한다.

## 2. 관련연구
디지털 사후 아바타 연구는 상호 동의, 투명성, 서비스 종료 책임을 논의한다 [1]. RoleLLM은 역할 지식과 말투 모방을 다루며 [2], LoCoMo는 장기 대화의 사건·시간 기억을 평가한다 [3]. 본 연구는 이 문제의식을 기록 기반 시스템에 적용하되 장기 대화 적응이나 말투 프로필의 독립 효과를 검증하지 않는다.

RAGAS는 검색 문맥과 생성 답변을 나눠 평가하고 [4], CREPE는 거짓 전제 질의를 다룬다 [5]. RAG 기반 unlearning 연구는 검색 자료 통제와 모델 가중치의 지식 삭제를 구분한다 [6]. 본 연구는 이 평가와 실험을 재현하지 않고 합성 기록의 기권·근거 슬롯·정답·지어냄을 살핀다.

KoBEST는 개인 기록 근거성과 구별되는 외부 한국어 벤치마크다 [7]. 자동 판정과 사람 평가의 차이를 다룬 연구에 따라 [8], KoBEST와 자체 기록 평가 및 자동·수동 결과를 각각 구분한다. 결과는 합성 과제에 한정되며 새로운 범용 한국어 벤치마크를 제안하지 않는다.

## 3. 시스템 상세 설계
전체 시스템 흐름은 그림 1과 같으며 AI 부분은 오프라인 검색 v2와 guarded 프롬프트로 구성된다. 검색 v2는 질문 단위 기권과 원기록 문맥 복원을 결합하고 생성 프롬프트를 고정해 평가했다. 변경·삭제 전파의 검증은 후속 과제로 남는다.
[3.1 백엔드]
FastAPI 백엔드는 앱 요청을 라우터·서비스·클라이언트·DB 모듈에서 처리한다. 앱은 Supabase Auth로 인증한 뒤 Bearer JWT를 보내고, 백엔드는 토큰에서 사용자 ID를 확인한다. 본문 ID는 권한 근거로 쓰지 않으며 앱은 DB에 직접 접근하지 않는다. 대화는 turn_id별 STT·AI·TTS 단계로 처리하고 백엔드가 DB에서 최근 20쌍을 조회해 AI에 전달한다. 재전송 때 완료된 단계는 재사용하고, 하나의 요청만 단계를 선점해 처리하며 시도 횟수가 일치할 때만 결과를 저장한다. 응답 음성은 저장하지 않고 TTS 실패 때 텍스트를 유지하며 AI 생성 표시를 제공한다.

[3.2 데이터베이스 설계]
Supabase PostgreSQL에서는 대화방·턴·기록·텍스트 버전·말투 프로필·검색 청크를 대화 상대별로 연결한다. 확정 텍스트를 수정하면 새 버전으로 기록하고, 프로필에는 원본 개정 번호를 저장해 자료 변경 시 갱신 대상으로 표시한다. 텍스트 버전·검색 청크는 사용자·대화 상대 식별자를 상위 기록과 함께 검사하는 복합 외래 키를 사용한다. 조회에는 RLS를 적용하고 쓰기 권한은 백엔드에서 확인한다. 검색 대상은 동의된 현재 확정본으로 한정하며 임베딩 차원 제약과 복합 인덱스를 사용한다.

[3.3 앱]
Flutter 기반 Android·iOS 앱의 홈·기록·대화·설정 흐름을 설계했다. 로그인·가입은 앱에서 Supabase Auth로 처리하며 DB 테이블에 직접 접근하지 않는다. 홈에는 대화 상대·프로필·기록 상태를 표시한다. 기록은 이용 동의, 카카오톡 화자·제공자 선택, 음성 전사문 확인·수정을 지원하도록 설계했다. 기록을 기반으로 프로필을 생성하며, 이는 수정·삭제할 수 있다. 대화에는 AI 생성 표시와 근거 파일명·날짜·발췌문, 음성 처리 단계를 제공하고 재생 전 합성 음성임을 알린다. 기록 삭제 시에는 연관 자료와 프로필 반영분을 함께 제거한다.

## 4. 시스템 구현 결과
### 4.1 구성요소 현황
[앱]
로그인·가입 UI를 구현했으며 현재 인증 점검에는 더미 인증을 사용한다. Supabase Auth 어댑터 코드는 작성했으나 앱에서 아직 활성화하지 않았다. 텍스트·음성 대화와 대화 이력 화면의 코드, 기록 업로드·전사문 검토·삭제 화면의 코드도 구현되어 있다. 말투 프로필 화면은 아직 구현 중이다. 실제 인증과 백엔드 연동은 로컬 환경에서 진행 중이다. 서비스 E2E 검증과 실기기 음성 검증은 남아 있다.

[백엔드]
FastAPI는 상태 확인, 대화방 생성, 텍스트·음성 대화, 답변 TTS와 점검용 STT·TTS API를 제공한다. AI는 고정 응답 Mock과 계약 기반 원격 호출을, STT·TTS는 Mock을 지원한다. 가짜 DB·AI 시험은 pytest 204건 중 197건 통과, 7건 건너뜀이다. ElevenLabs·실제 Supabase·AI 연결은 검증 전이며 기록·프로필·검색 v2는 서비스 경로에 구현되지 않았다.


[데이터베이스]
원격 Supabase에 테이블 9개를 적용하고 Python 접근 함수 32개를 반영했다. 합성 자료와 임시 계정 2개로 저장·조회, 계정 분리, 일반 사용자 토큰의 직접 쓰기 및 서버 전용 함수 호출 차단, 턴 실행권·이전 시도 결과 거부, 확정본 검색·삭제 요청 기록 제외를 확인했다. 성능·파일 업로드·삭제 전파와 앱 E2E는 미검증 또는 연동 진행 중이다.

### 4.2 모델 비교
표 1은 여섯 후보의 기록 QA·지시 이행과 외부 KoBEST 결과를 정리한다. QA·지시 최고값보다 5%p 이내인 Qwen3-4B와 Qwen3-8B는 동률이다. KoBEST 평균은 Qwen3-4B가 59.62%, Qwen3-8B가 64.01%여서 Qwen3-8B를 조건부 추천했지만 서비스 모델은 미정이다. QA·지시는 각 20문항×3라운드로 반복해 독립 표본이 아니다. 작성자 1인(120응답·480평점)의 근거성은 Qwen2.5-7B 4.10/5, Qwen3-8B 2.95/5로 차이를 보였다.

### 4.3 프롬프트 실험
표 2는 안전 정의가 다른 두 프롬프트 실험을 비교한다. 1차 안전은 위험 문항에서 전제 수용과 지어냄이 없는 상태다. guarded는 안전을 Qwen3에서 9/24에서 22/24로, Qwen2.5에서 15/24에서 22/24로 높였지만 대조 정답은 낮추고 과잉 거절은 늘렸다. 2차 안전은 근거성 3/5 이상이다. guarded-v3에서 안전은 73/80에서 66/80으로, 압박 거짓 전제 안전은 7/8에서 3/8로 낮아졌고 과잉 거절은 3/28에서 1/28로 줄었다. 안전 정의가 달라 두 지표는 합산하지 않는다. g7-calm은 말투 지시 후보이며 효과는 별도로 측정하지 않았다.

표 2. 프롬프트 실험별 안전 정의와 핵심 정답·과잉 거절

### 4.4 검색 v2와 생성 평가
표 3은 보정 코퍼스(페르소나 5·기록 100·질문 80)와 별도 held-out(페르소나 5·사건군 20·기록 40·질문 48)의 결과를 제시한다. 완전 슬롯 문항(필요 근거 슬롯 전체 포함)은 검색 v1에서 v2로 바뀌며 42/60에서 57/60으로, 포함 슬롯(검색된 필요 근거 슬롯 수)은 157/186에서 181/186으로 늘었다. 고정 프롬프트 생성 정답은 47/80에서 58/80으로 늘고 지어냄은 15/80에서 9/80으로 줄었다.

held-out에서는 A(근거 없음)·B(검색 v2)·C(gold 근거) 조건으로 생성했다. 자동 판정(전체 문항)에서 B의 정답은 37/48로 A의 14/48보다 높았고, 지어냄은 2/48로 A의 8/48보다 적었다. 작성자 수동 채점(held-out 48건 표본, 조건당 16건) 근거성 A/B/C는 3.06/4.75/4.88점이며 A 과잉 거절은 7/16이었다. 자연스러움은 A/B/C 5.00/4.81/4.94로, 수동·자동 판정 정의가 다르다. 검색기는 무근거 질문 10개에서 빈 근거를 반환하지 못했고(0/10), 하게체 페르소나의 말높임 일치는 0/9였다. C는 진단용이지 배포 알고리즘이나 엄밀한 상한이 아니며, held-out은 검색 변경의 독립 효과를 입증하지 않는다.

## 5. 결론
사용자 확정 기록만 근거로 삼는 대화 시스템을 설계하고 모델·프롬프트·검색 v2를 오프라인 평가했다. 프롬프트 강화는 안전과 정답·과잉 거절의 상충을 보였고 검색 v2는 슬롯 포함·정답을 높이고 지어냄을 줄여 지어내기·거짓 전제를 일부 완화했다. 무근거 10문항에서 검색기가 빈 근거를 반환하지 못했고(0/10), 하게체 말높임 일치는 0/9였다. 평가는 합성 자료와 작성자 1인 표본에 한정되며 서비스 연동은 진행 중이고 모델은 미정이며 LoRA·말투 프로필 효과는 검증하지 않았다.
