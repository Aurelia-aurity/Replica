# `experiments/lora88`

Offline pure-PyTorch LoRA adapter and training skeleton. No service integration.

## Scope

- Existing school packages only: torch 2.7.1, transformers 4.57.1.
  No PEFT/TRL/bitsandbytes/datasets, installs or model downloads.
- Base weights are frozen; only FP32 `lora_A`/`lora_B` train. Adapter files
  contain tensors and exact declared base/config identity, not full weights.
  The format is project-specific, not PEFT-compatible.
- `LoRALinear.merge()` is eval-only. `train()` unmerges automatically.
  Unmerge restores base bytes exactly; bf16 merged inference has rounding error.
- All actual data, model files, checkpoints and logs belong outside tracked
  source. GPU execution requires separate user authorization and frozen inputs.
- The current DEV pilot has locally frozen criteria. It does not authorize a
  decision held-out run, longer training, environment changes or deployment.

## CPU checks

From the repository root in an existing torch + transformers + pytest environment:

```bash
python -m pytest experiments/lora88
python -m experiments.lora88.train --help
```

Tests instantiate tiny random models; no downloads, CUDA or weights are needed.
The adapter and loop require torch only; the actual offline-model CLI also
requires existing transformers.

## Interfaces and data boundary

`AdapterSpec` names every full Linear path, rank, alpha and base identity.
`inject`, `save_adapter`, `load_adapter` reject topology/config mismatch.
`train_epochs` accepts reviewed `Batch` tensors and `TrainConfig`, weights
accumulated loss by supervised shifted tokens, clips gradients and preserves
AdamW state between epochs. `on_epoch` can save/select DEV snapshots externally.

Each batch contains int64 `[1, sequence]` `input_ids`, `attention_mask`, `labels`.
Prompt and padding labels must be -100, supervised labels must equal input IDs,
and at least one shifted target must remain. The loop cannot infer the semantic
assistant boundary; the upstream reviewed tokenizer must establish that span.
It does not tokenize text, manufacture targets or validate provenance claims.

The CLI uses local files only:

```bash
python -m experiments.lora88.train --model-path /absolute/local/Qwen3-8B \
  --data /absolute/local/train.pt --protocol /absolute/local/approved.json \
  --protocol-sha256 APPROVED_PROTOCOL_SHA256 --output /absolute/local/new-run
```

This is a future invocation reference, not a launch instruction. The approved
JSON must contain `status: "APPROVED_FROZEN"`, `approved_by`, `approved_at`,
`model_path` (resolved absolute), `data_sha256`, `training` (TrainConfig fields)
and `adapter` (AdapterSpec fields; `targets` is an array). The supplied SHA256
binds the complete JSON. This is a review attestation, not user authentication.
No approval artifact is generated by this code.

`train.pt` is a torch `weights_only=True` payload with `split: "train"`,
`provenance: "reviewed-synthetic-dev"` and `batches`, a list of tensor mappings
with the three Batch keys. Never load arbitrary pickle objects or held-out data.
File identity, provenance and approval remain the execution owner's responsibility.

DEV configuration: Qwen3-8B36 layers q/v, rank8 alpha16, bf16 base and FP32
adapter, max_sequence4096, batch1, accumulation8, AdamW1e-4,
non-reentrant checkpointing, cache off. `prepare_data.py` builds newly authored
synthetic DEV from `synthetic.py` using existing offline KURE-v1/retrieval-v2
on independently reset scenario archives.300/60 train/validation families,
three registers×B/C, yield1800 full training and360 validation rows.
Actual long B rows span2362–2590 total tokens, without truncation.

`dev_job.py` runs ONE sealed offline DEV pilot: BASE evaluation, one epoch on
the fixed180-row pilot subset (23 updates), then merged LORA evaluation.
Each arm produces360 validation replies plus six warmups and six
4096-input/160-output memory probes. It records training throughput, allocator
and NVML memory, generator timing and immutable outputs. `dev.sbatch` uses the
existing school venv, exclusive one-GPU DIS02,42GiB limit and3-hour wall limit.

The narrow stem/ending templates and deterministic slot cycling do not establish
natural-corpus or broad-domain generalization. The register ending heuristic
is only a diagnostic; official judgments use the separately frozen automatic
hybrid pipeline. The old #77 arm registry is not reused as a LoRA runner.
There is no decision-set builder, service integration or training resume.
