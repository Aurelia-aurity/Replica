# #58 근거성 보완과 말투 프로필 적용을 위한 프롬프트 2차 실험 결과

## 요약

#55(PR #56)에서 채택한 `guarded` 시스템 프롬프트는 거짓 전제 수용과 지어내기를 줄였으나 기록에 있는 사실을 답한 뒤 "기록에 없다"고 덧붙이는 자기모순 응답과 대조 문항 정답 감소·과잉 거절 증가가 함께 나타났다. 또한 다음 API 계약 단계(`contracts/backend-ai`, PR #29 초안)에서 적용할 페르소나 말투 프로필 템플릿이 아직 없었다.

이슈 #58에서는 서빙 모델인 `Qwen3-8B`를 대상으로 라운드 1~7에 걸쳐 총 18개 조건(생성 `1456`개, Claude Sonnet 에이전트 판정 `1296/1296`개)을 실험하고 대표 3개 조건(`guarded`, `guarded-v3`, `style-g`)의 동일 36문항(총 `108`개 응답, 4개 항목의 평점 `432`개)을 작성자가 블라인드로 직접 채점했다.

- **기준선 재현**: 라운드 1 `guarded`는 #55의 `Qwen3-8B` 생성 결과를 토큰 해시 기준 `92/92` 그대로 재현했다(누락 `0`, 추가 `0`, 불일치 `0`).
- **근거성 프롬프트 수정(`guarded-v2a`, `guarded-v2b`, `guarded-v3`)**: 직접 답변을 강조하자 대조 문항 핵심 정답(`7/8` → `8/8`)과 과잉 거절(`3/28` → `0/28`~`1/28`)은 개선됐으나 전체 안전 통과(`73/80` → `66/80`)와 확인 압박 거짓 전제(`fp_confirm`) 안전(`7/8` → `2/8`~`3/8`)이 떨어졌다.
- **말투 프로필 결합 및 반복 수정(라운드 1~7)**: 단순 프로필 삽입 시 예시 문장 전체 복사(`style` `28/44`, `style-g` `20/44`), 페르소나 역할 부여 시 기억 지어내기 증가(`style-g4` 에이전트 안전 `41/80`, 지어내기 `38/80`), 반말 프로필 응답의 `'맞아'` 시작(`style-g5a` `6/80`, `style-g5b` `4/80`), 압박 방어 강화 시 부정 시작 급증(`style-g6a` `36/80`, `guarded-g6b` `47/80`)을 확인했다. 라운드 7에서는 조건부 전제 처리 규칙 틀을 5개 합성 프로필에 적용해 `g7-calm` 기준 안전 `74/80`, `fp_confirm` `8/8`, 자기모순 `2/80`(C 문항 `1/12`), 부정 시작 `2/80`을 확인했다.
- **권장안**: 현재 서비스 기본 프롬프트는 #55 `guarded`를 유지하고(최종 확정 아님), 말투 적용 시에는 라운드 7의 조건부 전제 처리 규칙 틀을 실험용 템플릿 후보(`g7-calm` 등)로 삼는다.

**PM 결정 (2026-10-27)**: 기본 시스템 프롬프트는 #55 `guarded`를 유지한다(최종본 아님). 말투 템플릿은 라운드 7 틀(`g7-*`)을 후보로 둔다. 다만 실제 대화 기록을 쓴 로컬 보조 평가에서 확인 압박 거짓 전제 방어가 약해 확정은 전제 확인을 분리한 2단계 설계를 검증한 뒤로 미룬다.

## 실험 조건

- **모델 및 실행 설정**: `Qwen3-8B`(revision `b968826d9c46dd6066d109eabc6255188de91218`), greedy 디코딩, 최대 생성 `160` tokens, `bf16`, `enable_thinking=False`, 조건당 `rounds=1`(환경 파일의 `config.rounds=3`은 기존 평가 설정에서 상속된 값이며 실제 반복 횟수는 `1`). 환경 파일에는 학교 GPU(`RTX A6000`), Python `3.12.7`, `torch 2.7.1+cu118`, `transformers 4.57.1` 실행 기록이 저장되어 있다.
- **평가 문항 구성**: 모든 문항은 개인정보가 없는 합성 데이터다.
  - **80문항 에이전트 판정 세트**(전체 문항 조건): #55 검증 문항 `32`개(`fp_confirm` `8`, `fp_soft` `8`, `no_record` `8`, `answerable` `8`) + 자기모순 확인 문항(`contradiction`) `12`개 + #36 사람 평가 문항(`human`) `20`개 + 일상 대화 문항(`style_chat`) `10`개 + 기록·말투 문항(`style_record`) `6`개. `80`문항 전체가 거짓 전제 문항인 것은 아니다.
  - **120문항 전체 생성 세트**(`guarded`, `guarded-v2a`, `guarded-v2b`, `guarded-v3` 4개 조건): 위 `80`문항 + 기록 QA `20`문항 + 지시 이행 `20`문항. 라운드 4~7 조건은 기록 QA와 지시 이행 자동 채점 세트를 실행하지 않았다.
  - **44문항 말투 일치 세트**(`style`, `style-v3`, `style-g`, `style-g2` 4개 조건): `fp_confirm` `2`, `fp_soft` `2`, `no_record` `2`, `answerable` `2`, `human` `20`, `style_chat` `10`, `style_record` `6`으로 구성한 `44`개 일치 문항.
- **채점 방식**:
  - **근거성 및 부작용 판정(Claude Sonnet 에이전트 판정)**: 사람 안전 채점이 아니라 Claude Sonnet 에이전트가 판정했다. 이번 실험에서 '안전(`Safe`)'은 #55의 불리언 정의가 아니라 에이전트 `grounding_1to5 >= 3`을 뜻한다. `core_correct`는 답할 수 있는 대조 문항(`answerable` `8`개 또는 `2`개)만 집계하고 `over_refusal`은 대조 문항과 사람 평가 문항(`answerable + human`, `28`개 또는 `22`개)만 집계한다.
  - **자연스러움·지시 이행·유용성·말투 반영도(작성자 블라인드 채점)**: 작성자 1명이 조건을 가린 채 단일 목표 프로필 기준으로 `guarded`, `guarded-v3`, `style-g` 3개 조건의 동일 `36`문항(총 `108`개 응답, 4개 항목의 평점 `432`개, 1~5점 정수)을 직접 채점했다. 채점 완료 후에만 블라인드 키를 대조해 `108/108` 응답 SHA-256 해시와 라운드별 블라인드 키 일치를 확인했다.
  - **기록 QA·지시 이행 자동 채점**: #36 채점 코드로 라운드 1·2의 `guarded` 계열 4개 조건을 채점했다.
  - **작성자 표본 검수**: 에이전트 판정에서 추린 표본 23개를 작성자가 검수했으며 동의 여부와 별도 의견은 아래 결과와 `judge/author-sample-review.csv`에 기록했다.

**작성자 표본 검수 결과 (2026-10-27)**: 라운드 1~7 에이전트 판정에서 라운드별로 3~4건씩 뽑은 23건(안전 미달 판정 9건 포함, 조건은 가림)을 작성자가 검수했다. 근거성 안전 판정 23/23, 자기모순 판정 23/23에 동의했다(`judge/author-sample-review.csv`). 별도 의견으로, 근거성 판정과 별개로 말투 습관 표현("천천히 해도 돼")을 문맥과 상관없이 반복하는 응답과 이모지 사용을 가장 큰 문제로 지적했다. 전체 생성 기준으로 "천천히 해도 돼"를 포함한 응답은 `style` 29/44, `style-g4` 60/80, `g7-calm` 11/80이었고 이모지를 금지한 `g7-playful`에서도 이모지 포함 응답이 36/80 나왔다.

- **라운드 1~2(직접 답변 강조의 상충 관계)**: `guarded-v2a`·`guarded-v2b`는 대조 문항 핵심 정답을 `7/8`에서 `8/8`로 높이고 과잉 거절을 `3/28`에서 `0/28`로 줄였으며 기록 QA 슬롯 점수(`0.7916666666666666` → `0.8416666666666667`, 정답 슬롯 수 `38/48` → `41/48`)도 개선했지만 전체 안전이 `73/80`에서 `66/80`으로 낮아지고 확인 압박 거짓 전제(`fp_confirm`) 안전이 `7/8`에서 `2/8`로 떨어졌다. 직접 답변을 강조한 지시가 거짓 전제 저항 약화와 함께 나타났으며 `guarded-v3`도 안전 `66/80`, `fp_confirm` `3/8`에 머물렀다. 따라서 기본 시스템 프롬프트는 #55 `guarded`를 유지한다.

## 한계

- 모든 조건은 조건당 1라운드(`rounds=1`)로 생성했으며 합성 문항 세트에서만 확인한 결과이므로 실제 사용자 대화나 실험하지 않은 프로필로의 일반화는 검증되지 않았다.
- 안전 및 자기모순·지어내기 지표는 사람이 아니라 Claude Sonnet 에이전트 단일 모델 판정(`grounding_1to5 >= 3`)에 기반하며, 작성자가 표본 23개를 검수해 근거성 안전 판정과 자기모순 판정에 모두 동의했다(`judge/author-sample-review.csv`). 다만 표본 검수 결과가 전체 응답에 대한 사람 판정을 대신하지는 않는다.
- 작성자 블라인드 사람 채점(`108`개 응답)은 라운드 1~3의 3개 조건(`guarded`, `guarded-v3`, `style-g`) 36문항에 대해서만 수행했으며 라운드 4~7 조건의 자연스러움·말투 반영도는 사람이 직접 채점하지 않았다.
- 라운드 4~7 조건은 기록 QA와 지시 이행 자동 채점 세트를 실행하지 않았다.
- 여러 지시 문구를 라운드마다 함께 수정했으므로 개별 문구(반말 어미, 특정 기억 표현, 직접 답변 지시 등)의 단독 인과 효과를 분리해 증명한 실험은 아니다.

요청자는 AI Hub 실제 대화 데이터로 한 로컬 보조 평가(원문·결과 파일은 저장소에 없음)에서 프롬프트 규칙만으로는 전제 안전성과 대화 자연스러움이 서로 상충한다는 결과를 보고했다. 다음 단계에서는 전제 확인을 분리하는 2단계 설계를 검토한다(초안의 출처 표기이며 미검증: 한국지능정보사회진흥원 AI Hub 한국어 멀티세션 대화). 이 보조 평가는 `score.py`로 검증한 저장소 내 실험이 아니며, 2단계 설계 역시 아직 구현이나 API 계약 변경으로 확정되지 않았다.
