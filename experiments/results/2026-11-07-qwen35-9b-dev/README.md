# Qwen3.5-9B DEV 실험 결과 (Issue #77 후속 비교)

## 1. 목적 및 범위

이 문서는 종료된 이슈 #77의 후속 작업으로, 후보 모델 `Qwen/Qwen3.5-9B`를 기존 조건부 기준선 모델 `Qwen/Qwen3-8B`와 동일한 합성 `DEV` 데이터셋에서 비교 실험한 결과를 정리한다. 실험 코드와 실행 구성은 [`../../model77/README.md`](../../model77/README.md)에 정리되어 있다.

* **실험 범위 (`DEV_ONLY`)**: 합성 `DEV` 24문항의 원본 `r1` 메시지 입력을 그대로 재사용했다.
* **비교 조건**: 검색 근거를 넣는 조건 B(`retrieval-v2` 검색 근거, 24문항)와 정답 근거를 넣는 조건 C(정답 근거, 24문항)를 합쳐 모델당 일반 호출 48건을 실행했다.
* **판정 제외 (`decision: false`)**: 이번 실행은 합성 `DEV` 범위에서만 확인한 보조 실험이며, 최종 모델 선정 관문 판정이 아니다. 새로운 결정용 평가 세트를 구축하거나 실행하지 않았고, 결정용 세트를 열람하지도 않았다.
* **채점 방식**: 총 96건(모델 2종 × 48건)의 응답은 자동 하이브리드 채점으로 평가했으며 기준에 따라 전체 심층 자동 재채점을 수행했다. 채점 상태가 유효(`VALID`)하다는 것은 96건의 자동 채점 레이블이 누락 없이 완성되었다는 뜻일 뿐, 후보 모델 선정이나 채택 판정을 의미하지 않는다.
* **재현 범위 안내**: 공개 저장소 코드만으로는 별도 보관된 비공개 원본 산출물과 완전히 동일한 결과를 재현할 수 없다.

## 2. 실험 환경 및 호출 구성

이번 실험에서는 기준선 모델(`Qwen/Qwen3-8B`)과 후보 모델(`Qwen/Qwen3.5-9B`) 모두 동일한 신규 실행 환경(`torch 2.7.1+cu126`, `transformers 5.22.2`)에서 실행했다.

* **기준선 모델**: `Qwen/Qwen3-8B`
  * 리비전: `b968826d9c46dd6066d109eabc6255188de91218`
  * 모델 유형(`model_type`): `qwen3`
* **후보 모델**: `Qwen/Qwen3.5-9B`
  * 리비전: `c202236235762e1c871ad0ccb60c8ee5ba337b9a`
  * 모델 유형(`model_type`): `qwen3_5`
* **호출 구성**: 각 모델은 조건 B 24문항과 조건 C 24문항을 합쳐 총 48건의 일반 호출을 수행했다. 측정에서 제외되는 예열(warmup) 호출은 모델당 6건씩 먼저 실행했으며 별도의 부하(stress) 호출은 실행하지 않았다. 두 모델 모두 일반 호출 48건에서 160토큰 길이 제한에 도달한 응답(`length_cap_count`)은 0건이었다.

## 3. DEV 평가 결과

아래 핵심 요약 표는 모델별·조건별 24문항에 대한 주요 품질 지표와 생성 지연 시간(`p95`)을 비교한 결과다.

| 모델 | 조건 | core | fabricated | register | 하게체 | p95(초) |
| --- | --- | --- | --- | --- | --- | --- |
| `Qwen/Qwen3-8B` | B (`retrieval-v2` 검색 근거) | 18/24 | 5/24 | 16/24 | 0/8 | 4.314 |
| `Qwen/Qwen3-8B` | C (정답 근거) | 21/24 | 4/24 | 16/24 | 0/8 | 5.303 |
| `Qwen/Qwen3.5-9B` | B (`retrieval-v2` 검색 근거) | 19/24 | 8/24 | 7/24 | 0/8 | 6.654 |
| `Qwen/Qwen3.5-9B` | C (정답 근거) | 22/24 | 8/24 | 8/24 | 0/8 | 6.300 |

* **핵심 정답(`core`) 및 지어냄(`fabricated`)**
  * `Qwen/Qwen3.5-9B`는 핵심 정답이 조건 B 19/24, 조건 C 22/24로 `Qwen/Qwen3-8B`(조건 B 18/24, 조건 C 21/24)보다 각 1건씩 많았다.
  * 반면 근거에 없는 내용을 지어낸 건수(`fabricated`)는 `Qwen/Qwen3.5-9B`가 조건 B 8/24, 조건 C 8/24로 나타나 `Qwen/Qwen3-8B`(조건 B 5/24, 조건 C 4/24)보다 오히려 늘어났다.
* **말투 일관성(`register`) 및 하게체**
  * `Qwen/Qwen3-8B`는 말투 일관성에서 조건 B와 C 모두 16/24를 기록했다.
  * `Qwen/Qwen3.5-9B`는 조건 B 7/24, 조건 C 8/24에 그쳐 말투 유지 성능이 기준선보다 크게 낮아졌다.
  * 하게체 문항(8문항)은 두 모델 모두 조건 B·C에서 0/8을 기록해 한계를 해결하지 못했다.

## 4. 운영 측정 및 해석 한계

신규 환경(`torch 2.7.1+cu126`, `transformers 5.22.2`)에서 측정한 적재 시간, 지연 시간, 메모리 최고치는 다음과 같다.

* **지연 시간 측정 범위**: 표에 제시한 `p95` 지연 시간(`Qwen/Qwen3-8B` 조건 B 4.314초·조건 C 5.303초, `Qwen/Qwen3.5-9B` 조건 B 6.654초·조건 C 6.300초)은 단일 요청의 프롬프트 렌더링, 토크나이징, 텐서 GPU 복사(H2D), 프리필, 디코드, CUDA 동기화, 텍스트 디코딩을 합산한 로컬 생성 구간 시간이다. 모델 초기 적재, 문서 검색, API 서버 처리, 네트워크 전송 시간은 제외되어 있으므로 서비스 종단 간(E2E) 지연 시간이 아니다.
* **모델 적재 시간(`load_s`)**: `Qwen/Qwen3-8B`는 20.717초, `Qwen/Qwen3.5-9B`는 143.158초가 소요되었다.
* **메모리 최고치(Peak Memory)**: 일반 호출 구간(`normal`) 기준 NVML 최고치는 `Qwen/Qwen3-8B`가 23.263 GiB(할당 최고치 17.222 GiB, 예약 최고치 21.727 GiB), `Qwen/Qwen3.5-9B`가 22.352 GiB(할당 최고치 18.535 GiB, 예약 최고치 20.736 GiB)로 측정되었다.
* **커널 및 메모리 해석 주의사항**
  * 실행 환경에 선택 패키지인 `causal_conv1d`와 `flash-linear-attention`이 설치되어 있지 않아, `Qwen/Qwen3.5-9B`는 참조용 PyTorch 커널 경로로 동작했다. 따라서 이번 지연 시간 측정치는 최적화된 커널 기준 벤치마크가 아니다.
  * 이번 실험에서는 별도의 부하(stress) 호출을 실행하지 않았다. NVML 최고치(23.263 GiB 및 22.352 GiB)는 일반 호출 48건 구간에서만 관측된 값이며, 최대 문맥 길이나 고부하 상황에서의 메모리 안정성을 보장하는 수치가 아니다.

## 5. 실행 호환성 및 기준선 동등성

신규 환경에서 두 모델을 실행하면서 조치한 API 호환성 수정 사항과 기존 기준선 실행 대비 동등성 확인 결과는 다음과 같다.

* **`transformers 5.22.2` 호출 호환성 수정**: 첫 실행 시도에서는 기준선 모델의 첫 번째 예열 호출에서 `transformers 5.22.2`가 `use_model_defaults=False`를 사용되지 않는 인자(`unused model_kwargs`)로 거부하는 API 오류가 발생했다. 이를 해결하기 위해 `generate` 함수의 시그니처를 검사하여 `use_model_defaults`가 명시적 매개변수로 존재할 때만 `False`를 전달하고, 없으면 생략하도록 실행 코드를 수정했다. 명시적인 그리디(greedy) 생성 설정은 그대로 유지했으며 수정 후에는 두 모델 모두 모델당 예열 6건과 일반 호출 48건을 오류 없이 마쳤다.
* **기준선(`Qwen/Qwen3-8B`) 실행 동등성 대조**: 기존 이슈 #77의 기준선 실행 환경(`transformers 4.57.1` / `cu118`)과 이번 신규 실행 환경(`torch 2.7.1+cu126` / `transformers 5.22.2`)에서 각각 실행한 `Qwen/Qwen3-8B`의 일반 호출 48건을 대조했다.
  * 입력 메시지 구성은 동일하며, 렌더링된 프롬프트 해시(`rendered_sha256`)와 입력 토큰 ID 해시(`input_ids_sha256`)가 48/48건 모두 일치해 모델에 전달된 입력이 완전히 동일함을 확인했다.
  * 생성된 출력 텍스트와 토큰 ID는 48건 중 37건(37/48)이 정확히 일치했고, 나머지 11건에서 차이가 발생했다.
  * 차이가 발생한 11건도 인위적으로 다시 생성하지 않고 그대로 채점에 반영했다. 이번 실행에서는 PyTorch/CUDA 빌드(`cu118` → `torch 2.7.1+cu126`)와 `transformers` 버전(`4.57.1` → `5.22.2`)이 함께 변경되었기 때문에, 11건의 출력 차이가 어느 요소의 변경 때문인지는 분리해 단정할 수 없다.

## 6. 결론 및 향후 방침

1. **품질 및 지연 시간 비교**: `Qwen/Qwen3.5-9B`는 합성 `DEV`에서 핵심 정답(`core`, 조건 B 19/24, 조건 C 22/24)이 `Qwen/Qwen3-8B`보다 조건별로 1건씩 많았으나 지어냄(`fabricated`, 조건 B·C 모두 8/24)이 늘고 말투 일관성(`register`, 조건 B 7/24, 조건 C 8/24)이 크게 하락했다. 또한 하게체(0/8) 한계도 해결되지 않았으며, 선택 커널이 없는 참조용 PyTorch 경로에서 `p95` 지연 시간(조건 B 6.654초, 조건 C 6.300초)도 기준선보다 길었다.
2. **측정 및 판정 한계**: 이번 실험은 합성 `DEV` 24문항만 사용한 보조 확인(`decision: false`)이며, 새로운 결정용 세트 구축이나 선정 관문 실행을 포함하지 않는다. 부하(stress) 구간 메모리 검증과 최적화 커널 벤치마크도 수행하지 않았다.
3. **기준선 유지**: 위 결과를 바탕으로 기존 이슈 #77에서 수립한 `Qwen/Qwen3-8B` 조건부 기준선을 그대로 유지하며, 최종 서비스 모델 선정은 아직 확정하지 않은 상태(미정)로 둔다.
