# 이슈 #100 화자 귀속 단일 변경(O3) DEV 실험 결과

이 문서는 이슈 `#100`의 화자 귀속 단일 변경 후보(`A`, O3)를 기준선(`B`) 및 정답 페르소나 진단 대조군(`C`)과 비교한 `DEV-v3` 결과와, 별도 1회 후속 확인(`confirm-v3`)의 실행·중단 기록을 정리한다.

---

## 1. 목적 및 범위

`#95` 실험에서 기준선(`Qwen/Qwen3-8B` + `r1` + `retrieval v2`)은 정답 근거가 검색되어도 정보 제공자나 제삼자의 기록을 페르소나 본인의 경험으로 혼동하는 오류가 관찰되었다. 이번 실험에서는 모델 입력 렌더링 단계에 한해 제공자·제삼자 출처 설명을 덧붙였다. 이 단일 변경(`O3`)이 화자 귀속 오류를 줄이고 근거성, 핵심 사실 정답률, 안전한 답 보류, 일상 대화 품질의 비열등성을 유지하는지 검증한다.

평가 문항과 응답에는 신규 합성 데이터(`DEV-v3`, `confirm-v3`)만 사용했고 봉인된 홀드아웃 세트는 사용하지 않았다. 채점기 사전 검증에는 `#95` DEV 응답 30건(각 2회)을 썼지만 평가 기준을 조정하는 데 사용하지 않았다. 모델 교체, LoRA 학습, 새 패키지 설치, 서빙 엔진 변경, 실제 서비스 연동은 범위에서 제외했다. 실험 동결 시점(2026-11-09)에는 `Qwen/Qwen3-8B`가 조건부 기준선이었으며, 이후 2026-11-10 결정으로 서비스 모델이 `Qwen3-8B`로 확정되었다.

### 2.4 사전 통과 관문

- 주 지표(우월성): 고정 360문항에서 `B` 오류/`A` 무오류(`g`)와 `B` 무오류/`A` 오류(`l`)를 비교해 단측 정확 McNemar `p <= 0.05` 및 오류 감소 `(g - l) / 360 >= 0.05` (5%p 이상)를 모두 충족해야 한다.
- 비열등성(4개 관문, 가족 유의수준 `0.05`, Bonferroni 보정 관문당 단측 `alpha = 0.0125`): `B` 성공·`A` 실패 건수만 계상하는 단측 98.75% Clopper-Pearson 상한이 각 마진 이하이어야 한다.
  - `grounding` (1,320문항): 마진 `0.03` (허용 손실 최대 25건)
  - `core_correct` (720문항): 마진 `0.03` (허용 손실 최대 11건)
  - `safe_abstention` (300문항): 마진 `0.05` (허용 손실 최대 6건)
  - `chat_success` (300문항): 마진 `0.05` (허용 손실 최대 6건)

## 6. 채택 여부, #74 계약 확인, 한계 및 다음 단계

### 6.1 채택 여부

**사전 동결 관문을 통과하지 못해 O3에 대한 서비스 채택 승인은 없으며, AI 파트 담당자(이슈 담당자)는 2026-11-25에 O3를 서비스에 채택하지 않기로 확정했다.** `DEV-v3`에서 화자 귀속 주 지표와 일상 대화 비열등성은 통과했으나 근거성·핵심 사실 정답·안전한 답 보류 비열등성 관문을 통과하지 못했고, `confirm-v3`는 채점 중단으로 미결론에 머물렀다.

### 6.2 #74 계약 확인 현황

설계 단계에서 2026-11-09 시점의 `#74` 이슈(최종 갱신 2026-11-02, DB 담당 댓글 포함) 및 백엔드-AI 교환 스키마를 확인했다. `DEV` 실험은 교환 스키마를 변경하지 않고 모델 입력 렌더링 단계에서만 제공자·제삼자 출처 설명을 덧붙였으며, 다른 파트와의 별도 조율 기록은 없다.

2026-11-09 설계 확인 시점에 `#74`에 열려 있던 항목은 다음과 같다.

- 발화·청크 단위 필드 부재
- 실제 서비스 화자 매핑 구현 및 마스킹
- 제공자(provider) 선택 계약 작업

이후 계약 문서는 추가 갱신되었으며(2026-11-10 제공자 역할을 `SC-04` 선택 기준으로 정합화, 2026-11-23 `#117` 병합), 현재 `main` 브랜치의 `contracts/backend-ai/api-spec.md`에는 `speaker_role`(`persona`/`provider`/`other`)과 제공자 선택 `SC-04`가 정의되어 있으나 이 문서는 갱신된 계약을 기준으로 `#74`를 다시 대조하지 않았다. 위 항목의 현재 해소 여부는 확인하지 않았으며, 필요 시 `#74`에서 별도로 논의한다.

### 6.3 한계 및 미확인 사항

- `confirm-v3`는 채점이 중단되어 최종 라벨·점수·관문 판정이 없으며, 종료 시각과 실패 호출의 완전한 사용량도 기록되지 않았다.
- `confirm-v3` 생성물에 대한 별도 검증 JSON은 없으며, 원격 파일 SHA-256과 Slurm 회계 정보는 독립 재확인하지 않았다.
- 이번 PR에 포함된 일부 동결 파일에는 학교 서버 계정명·경로와 로컬 작업 경로(절대경로 1건 포함)가 포함되어 있으나 동결 해시에 묶여 있어 수정할 수 없다. 해당 파일이 참조하는 채점·판정 도구는 저장소 밖 로컬 경로에 있으므로 저장소만으로는 채점을 재실행할 수 없다.
- 검색 준비 팩(`pack.json`), 생성 응답(`generations.jsonl`), 채점 산출물과 로그는 저장소에 포함하지 않았고 SHA-256 해시로만 식별한다.
- 모든 평가는 합성 데이터와 자동 채점에 기반하므로 실제 사용자 기록에 대한 일반화, 사람 기준 정답 대비 정확도, 시간 오류 양성 민감도는 입증되지 않았다.
- `#74` 기반 실제 서비스 화자 매핑 구현과 운영 검증은 완료되지 않았다.
