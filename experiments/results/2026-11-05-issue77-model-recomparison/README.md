# 이슈 77 서비스 모델 재비교 실험 및 3개 라운드 판정 기록 (2026-11-05)

## 1. 실험 목적 및 범위

본 문서는 `retrieval-v2` 고정 근거 및 생성 프롬프트 조건 아래에서 기존 서비스 기준선 모델(`Qwen/Qwen3-8B`)과 신규·대형 후보 모델을 동일 규격으로 비교한 3개 라운드 실험의 절차, 판정 기준, 정량 결과 및 결론을 기록한다.

- 핵심 목적: 동일한 근거 주입 조건(`B: retrieval-v2`, `C: canonical gold evidence`)에서 후보 모델이 품질 하한·상한, 화법(register) 준수, 지연 시간(p95), GPU 메모리 상한을 모두 만족하며 기존 기준선 대비 통계적 우위를 입증하는지 확인한다.
- 최종 상태 요약: 3개 라운드에 걸쳐 모든 필수 게이트를 동시에 통과한 교체 후보 모델은 없었다. 이에 따라 기존 `Qwen/Qwen3-8B` 기준선을 유지하며, 본 실험 결과만으로 최종 서비스 운영 모델을 확정하거나 승인하지 않는다.

## 3. 실행 환경, 평가 데이터셋 설계 및 자동 판정·감사 절차

### 3.1 하드웨어 및 추론 런타임

- 소프트웨어 환경: 기존 서버 환경인 `Python 3.12.7`, `torch 2.7.1+cu118`, `transformers 4.57.1` 고정.
- 하드웨어: 단일 NVIDIA RTX A6000 48GB (`DIS02` / 파티션 `p02`).
- 디코딩 및 실행 규격: `bf16`, `eager` 어텐션, 배치 크기 `1`, 그리디 디코딩(greedy), `max_new_tokens=160`, 요청당 타임아웃 `30s`.
- 지연 시간(Latency) 측정 범위: 생성기 벽시계 시간(프롬프트 렌더링, 토크나이징, H2D 복사, 프리필, 디코드, CUDA 동기화, 응답 텍스트 디코딩 포함)만 측정한다. 모델 초기 적재, 배치 큐 대기, 검색(`retrieval-v2`), 네트워크/API 통신, 사후 채점 시간은 제외되므로 종단간(E2E) 응답 시간이나 첫 토큰 도달 시간(TTFT)이 아니다.

### 3.2 라운드별 독립 봉인 데이터셋 및 사전 기준 변경 원칙

본 실험의 3개 라운드는 동일한 프롬프트와 기준으로 단순 3회 반복 측정한 실험이 아니다. 각 라운드는 이전 라운드의 실패 원인을 진단한 뒤, 생성 실행 전에 프롬프트 또는 판정 기준을 사전 개정하여 동결하고, 매 라운드마다 새롭게 독립 봉인된(separately sealed) 합성 평가셋에서 단 1회 본 실행했다.

- 문항 구성 (라운드당 240문항): 6개 페르소나에 걸쳐 단일 사실(`single`) 48문항, 다중 사실(`multi`) 48문항, 허위 전제(`false premise`) 48문항, 모호성(`ambiguity`) 24문항, 답변 불가(`unanswerable`) 48문항, 일반 대화(`ordinary chat`) 24문항으로 구성된다.
- 화법(Register) 배분: `하게체`, `해요체`, `반말` 각 80문항씩 총 240문항.
- 근거 주입 조건: 각 모델(또는 실험군)은 동일 240문항에 대해 ` 조건 B(retrieval-v2 검색 근거)` 240건과 `조건 C(canonical gold evidence 정답 근거)` 240건을 각각 생성하여 모델/실험군당 총 480개 응답을 산출한다. 통계적 추론 시 조건 B와 조건 C의 표본 크기를 합산(pooling)하지 않는다.

### 3.3 자동 하이브리드 채점 및 무작위 감사(Audit) 규칙

채점은 사람이 직접 검수하는 수동 감사가 아니라, 1차 자동 스크리닝 후 2차 심층 자동 채점으로 이어지는 자동 하이브리드 판정 파이프라인으로 진행했다.

- 전체 재채점(Fallback) 발동 조건: 무작위 감사 표본에서 전체 필드 기준 불일치율이 5%를 초과하거나, 날조(`fabricated`)/핵심 사실(`core`) 항목 불일치율이 2%를 초과할 경우 전체 응답에 대해 심층 자동 재채점을 전면 수행한다.
- 라운드별 감사 결과:
  - Round 1: 감사 표본 `227`건 중 불일치 `25`건(`11.01%`) 발생 -> 기준 초과로 전체 `2,400`건 자동 심층 재채점 수행.
  - Round 2: 감사 표본 `241`건 중 불일치 `16`건(`6.64%`) 발생 -> 기준 초과로 전체 `2,400`건 자동 심층 재채점 수행.
  - Round 3: 본선 선택군(`SELECTION`, `BASE`+`CAND`) 감사 표본 `106`건 중 불일치 `6`건(`5.66%`) 발생 -> 기준 초과로 본선 `960`건 전체 자동 심층 재채점 수행. 진단군(`DIAG`)은 감사 표본 `47`건 중 불일치 `1`건(`2.13%`)으로 전체 재채점 미발동.

## 4. 라운드별 사전 기준 변화 및 게이트 정의

### 4.1 라운드별 설계 변경 요약

1. **Round 1 (`r1` 프롬프트 + 절대 품질 기준)**:
   - 기본 `r1` 프롬프트를 사용하고, 절대 품질 하한·상한 게이트와 지연 시간(`조건 B p95 <= 6.000s` 및 `기준선 조건 B p95의 1.5배 이하`), 피크 메모리(`<= 42.000 GiB`)를 모두 요구했다.
   - 실행 결과 5개 모델 모두 화법(`S1`~`S4`) 및 다수의 품질 게이트에서 탈락했다. 특히 `하게체`(80문항) 준수는 `kanana-2-3b-instruct`만 조건 B `2/80`, 조건 C `1/80`을 기록했을 뿐 나머지 4개 모델은 모두 `0/80`에 그쳤다.
2. **Round 2 (`r1-reg` 공통 명시적 화법 지시문 + 상대 품질 허용치 전환)**:
   - Round 1의 화법 붕괴가 프롬프트 내 화법 규칙 명시 부족 때문인지 확인하기 위해, 모든 모델에 공통 명시적 화법 지시문을 추가한 `r1-reg` 프롬프트를 도입했다.
   - 판정 기준을 기준선(`Qwen3-8B`) 대비 상대 품질 게이트(`G1`~`G8`, `S1`~`S6`)와 조건 B 통계적 우위 검증으로 전환했다. 기존 Round 1의 절대 준비도 기준은 보고 전용(report-only) 참고치로만 유지하고, 지연 시간은 상대 게이트(`OPR1: 후보 B p95 <= 1.5 * 기준선 B p95` 및 모든 요청 `<= 30s`)로 전환했다(`6s` 절대 상한은 비게이트 전환, 피크 메모리 `<= 42.000 GiB` 게이트는 유지).
3. **Round 3 (14B 전용 화법·근거 보강 `r1-reg-14b` 대조 실험)**:
   - Round 2에서 `Qwen3-14B`가 조건 B 핵심 사실(`core`) 우위를 보이고도 화법(`S1`~`S3`) 및 일부 안전/부정 게이트(`G5`, `G7`)에서 탈락함에 따라, DEV 전용 수정을 거쳐 선택된 리비전 1 프롬프트(`r1-reg-14b`)를 `Qwen3-14B`에 적용하였다.
   - 본선 비교는 `BASE`(`Qwen3-8B` + `r1-reg`) 대비 `CAND`(`Qwen3-14B` + `r1-reg-14b`)로 구성하고 프롬프트 자체의 효과를 분리 관찰하기 위한 정보 제공용(informational only) 진단군 `DIAG`(`Qwen3-8B` + `r1-reg-14b`)를 함께 실행하였다.

### 4.2 상대 품질·화법 게이트 정의 (Round 2 & Round 3 공통, 기준선 $b$ 대비)

지표마다 분모가 다르다. 전체 응답 지표는 `240`건, 사실 문항 `G2`와 `G6`의 사실 문항 거절은 `168`건, 허위 전제 `G4`와 답변 불가 `G7`은 각각 `48`건, 일반 대화 `G8`은 `24`건이다. 화법별 `S2`는 `80`건, 페르소나별 `S3`는 `40`건, `S4` 자기 높임 프로브는 `72`건을 사용한다. Round 2와 Round 3에서 후보가 최종 통과하려면 조건 B와 조건 C의 모든 상대 게이트(`G1`~`G8`, `S1`~`S6`) 및 운영 게이트(메모리·지연 시간)를 통과하고, 동시에 조건 B의 두 주요 종점(`core` 정답 증가 또는 `fabricated` 날조 감소) 중 적어도 하나(at least one endpoint)에서 통계적 우위를 입증해야 한다.

| 게이트 ID | 평가 항목 | 기준선 측정치($b$) 대비 통과 조건 | 비고 (분모) |
| --- | --- | --- | --- |
| **G1** | 전체 핵심 사실 정확도 (`core`) | $\ge b - 5$ | 전체 240문항 |

### 7.2 후보 모델별 라이선스 제약 (동결된 이슈·후보 노트 기준)

본 절은 실험 착수 시 동결된 이슈 및 후보 검토 노트를 요약한 것이며, 새로운 법률 자문이나 추가 법무 검토 결과는 없다.

- `Qwen/Qwen3-8B`, `Qwen/Qwen3-14B`: Apache-2.0 라이선스.
- `K-intelligence/Midm-2.0-Base-Instruct`: MIT 라이선스.
- `kakaocorp/kanana-2-3b-instruct`, `kakaocorp/kanana-1.5-15.7b-a3b-instruct`: 연구용 비교 실험과 실제 서비스 도입 자격을 구분해야 한다. API, SI, 온프레미스 등 제3자 제공 형태의 상용 서비스 활용 시 별도의 상용 라이선스 협의가 필요하며, 배포 시 `Powered by Kanana` 표기 의무가 존재한다. 해당 라이선스 조건이 해결되기 전까지 Kanana 계열 모델은 서비스 운영 모델로 채택하지 않는다.

---

### 7.3 자동 판정과 단회 실행의 한계

공개된 모든 점수는 사람이 직접 매긴 결과가 아니라 자동 하이브리드 판정으로 산출한 값이어서 판정 오류나 편향이 발생할 수 있으며 사람 간 일치도를 측정한 결과도 아니다. 또한 각 독립 봉인 라운드는 데이터·프롬프트·기준을 달리해 생성기를 1회만 실행했고 동일 조건의 GPU 반복 실행으로 실행 간 분산이나 안정성을 측정하지 않았으므로 최종 서비스 모델은 아직 확정하지 않은 상태로 둔다.

## 8. 저장소 내 재현 도구 경로 및 재현 범위 제한

저장소에는 프롬프트 구성, 실험군 빌드, 입력 길이 감사와 생성 실행 도구가 포함되어 있다. 자동 채점과 최종 판정 집계 코드는 별도로 보관한다.

- 이슈 77 모델 비교 실행 도구 (`experiments/model77/`):
  - `experiments/model77/README.md`: 실행 절차 및 옵션 안내
  - `experiments/model77/profiles.json`: Stage 1 5개 모델의 고정 리비전 및 채팅 템플릿 프로필
  - `experiments/model77/prompt.py`, `experiments/model77/register-template.json`, `experiments/model77/register-14b-template.json`: 라운드별 화법 지시문 및 프롬프트 템플릿 렌더링
  - `experiments/model77/build_arm.py`, `experiments/model77/arms.py`: 실험군(Arm) 매니페스트 구성 및 조건 분리
  - `experiments/model77/prepare.py`, `experiments/model77/audit.py`, `experiments/model77/decision.py`, `experiments/model77/decision.sbatch`: 평가 입력 준비, 토크나이저별 입력 길이 감사, 생성 실행 및 Slurm 배치 스크립트
- RAG 근거 검색 및 생성 공통 모듈 (`experiments/rag/`):
  - `experiments/rag/README.md`
  - `experiments/rag/retrieval_v2.py`
  - `experiments/rag/generate.py`

> 재현 범위에 대한 중요 고지: 저장소에는 라운드별 독립 봉인 평가 코퍼스(sealed corpus), 모델 원시 생성 응답, 자동 채점기 입력/스크립트 및 동결 판정 기준 원문 파일이 포함되지 않는다. 따라서 본 문서에 보고된 수치와 완전히 동일한 정량 판정을 재실행하려면 별도로 보관된 동결 실험 산출물이 필요하며, 공개 저장소의 코드만으로는 동일한 수치 재현이 불가능하다.
