# Qwen2.5-7B-Instruct baseline 평가 결과

[이슈 #33](https://github.com/Aurelia-aurity/Replica/issues/33)의 첫 기준값이다. 2026-10-10 학교 GPU에서 실행하고 첫 라운드 20개 답변을 사용자가 직접 채점했다. 네 영역의 동일 가중 평균은 **3.75/5점**이다. 모델 비교에 사용할 기준값은 확보했지만, 현재 결과만으로 자연스러운 한국어 챗봇의 품질을 충족했다고 판단하지 않는다.

## 실행 조건과 자료

- 모델: `Qwen/Qwen2.5-7B-Instruct`. 로컬 가중치를 사용했으며 revision은 검증하지 못해 `null`로 기록했다.
- Python 3.12.7, torch 2.7.1+cu118, transformers 4.57.1, accelerate 1.15.0, safetensors 0.8.0.
- NVIDIA RTX A6000, CUDA0, BF16, eager attention. PyTorch CUDA build는 11.8이다. 드라이버 버전은 사용자가 보낸 `nvidia-smi`에서 525.105.17로 확인했으며 실행 메타데이터의 자동 기록값은 `null`이다.
- 시스템 프롬프트: `한국어로 간결하고 자연스럽게 답하세요.` Greedy 생성, 본 평가 상한 160토큰, 보충 상한 320토큰.
- 데이터: 합성 단일 턴 20문항, 영역별 5개, `replica-baseline-20` v1.0. 문항마다 새 system/user 메시지를 사용했다.
- 별도 질문 워밍업 3회 후 고정 순서로 3라운드 실행. 실패한 호출을 자동 재실행하지 않았다.
- #13 참조 commit: `705f2c2c9f9c0f426ac3376f9b9132021fb67139`. 실행 파일의 Git commit은 검증되지 않아 `null`이며 네 Python 파일의 내용 해시는 [metrics.json](metrics.json)에 있다.
- 실행 ID: `d7949d6f-f6b2-4e52-b9bc-e4239b44ffed`. 사용자가 전달한 원본을 검증했으며, 분석자가 학교 서버에서 직접 실행한 결과는 아니다.

[metrics.json](metrics.json)은 환경·호출별 집계·종료 상태·원본 해시, [human-scores.json](human-scores.json)은 사용자 점수와 이유, [assistant-analysis.json](assistant-analysis.json)은 별도 보조 분석을 담는다. 생성 응답 원문과 원본 저널은 저장소 밖에 보관한다. 점수의 `attempt_id`와 정확한 답변 문자열의 SHA-256, 원본 파일 해시로 판정 대상을 연결한다. 해시는 내용 연결 근거이며 실행자나 채점자의 신원을 인증하지 않는다.

U02는 세 라운드 모두 160토큰 상한에서 잘렸다. 각 응답의 보충 실행은 164토큰에서 EOS로 종료했다. 품질 채점에는 잘린 첫 라운드 원문을 사용했으며 보충 결과를 섞지 않았다. 모든 문항의 디코딩 결과는 세 라운드에서 같았다. 품질 표본은 서로 다른 20문항이며, 60개의 독립적인 품질 사례로 해석하지 않는다.

## 보조 분석과 개선 목표

외국어 혼용은 N02·N04·I01·G01, 20문항 중 4문항에서 관측됐다. N04와 I01은 한국어 답변으로 사용하기 어려운 수준이다. 현재 고정 설정에서 반복 재현됐지만, 모델 자체·프롬프트·적재 조건 중 어느 것이 원인인지는 확인하지 못했다.

I03은 필수 단어 `같이`를 누락했고 I05는 금지 단어 `휴식`을 사용했다. G04는 점심을 먹었다는 기록만으로 방문 목적을 추측했다. G05는 잘못된 전제에 동조하지 않고 제공한 기록대로 정정했다. N03·N05·U02에서는 제안이나 선택보다 사용자에게 선택 부담을 남긴 점이 아쉽다. U02에서 여러 기준을 제시한 것 자체는 요청 위반으로 보지 않는다.

보조 분석은 U01=3, U02=3, U04=4, G04=2를 제안했다. G04의 근거 없는 추측은 rubric의 2점 기준에 해당하지만 사용자가 선택한 3점은 그대로 보존했다. 이 네 문항의 의견은 전체 20문항에 대한 별도 공식 채점이나 독립 검토가 아니며 보조 전체 평균도 만들지 않았다.

영역 점수에 다른 영역의 문제가 섞인 한계가 있다. 예를 들어 G01은 장소를 지어내지 않았지만 외국어 혼용으로 감점됐다. 후속 비교에서는 네 영역 점수와 함께 외국어 혼용·필수 조건 누락·근거 없는 추측을 별도로 집계한다. 20개 합성 문항과 이번 설정으로 일반적인 오류율이나 전체 대화 능력을 추정하지 않는다.

다른 모델을 같은 조건으로 비교한 뒤 파인튜닝 대상을 결정한다. 개선 목표에는 한국어 유지, 자연스러운 대화, 기록에 없는 이유·동기·사건을 보충하지 않는 행동을 포함한다. 이번 기록에서 비교 모델 선정이나 파인튜닝 구현을 완료한 것으로 간주하지 않는다.

## 재사용과 완료 조건

실행·채점·결과 확인 명령은 [평가 README](../../baseline/README.md)에 있다. 후속 비교에서는 문항·rubric·시스템 프롬프트·상한·반복·워밍업·순서와 측정 경계를 유지한다. 모델 변경에 필요한 실행기 변경은 별도로 기록하고 검증한다. 비교용 메타데이터에는 모델과 검증된 revision 여부, tokenizer/template, dtype·양자화·attention, 패키지·GPU, 생성 옵션과 코드 해시를 남긴다. 조건이 달라지면 기존 실행으로 이어 쓰거나 단일 모델 변경 효과로 해석하지 않는다. 현재 실행기의 설정 검증을 몰래 해제해 다른 모델을 실행하지 않는다.
